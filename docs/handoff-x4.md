## 0. 한 문장

**길잡이가 도는 동안 세계를 세웠다 — 필드 잡몹 10기가 사라지고, 뒤에 생기는 적은
얼어붙고, 낮밤·체류·런 시계가 전부 멈춘다(2.35초 실창 관찰 `phase_drift=0.000`).
그리고 온보딩 4페이지에서 읽을 글자를 1,798자 → 1,197자(−33%)로, 가장 긴 한 줄을
59자 → 31자로 깎았다.**

## 2. 동결 — 무엇이 멈추고 무엇이 도는가

### 2.1 왜 `get_tree().paused`가 아닌가 (판단 ①)

이유가 **둘**이고 둘 다 치명적이다.

1. U3 §1.2의 이유 그대로 — 스텝 ①②는 플레이어가 **실제로 걷고 대시해야** 넘어간다.
2. Godot 4의 트리 일시정지는 **물리 서버까지 멈춘다**("2D and 3D physics will be
   stopped"). 플레이어만 `PROCESS_MODE_ALWAYS`로 빼도 `move_and_slide()`가 설 자리가
   없다. 즉 ①을 우회해도 ②에서 죽는다.

그래서 **선택 동결**이다. 두 층으로 나뉘어 있다.

| 층 | 무엇 | 어디 |
|---|---|---|
| **시간축** | `world_running` 게이트 하나 | `_process()` |
| **노드축** | `set_physics_process(false)` | `_guide_freeze_sweep()` |

### 2.2 시간축 — `_process()`의 `world_running`

```gdscript
var world_running := not (guide_active and state == "playing")
```

| 멈추는 것 | 이유 |
|---|---|
| `elapsed_time += delta` | 런 시계. 튜토리얼을 읽은 시간이 등급에 얹히면 안 된다 |
| `clock.tick(delta)` | **낮밤 · 체류(dwell)**. 이것 하나가 "dwell 불이익 0"의 전부다 |
| `clock.descent_valve_ready()` 폴링 | 클럭이 안 도니 의미 없지만 짝을 맞춰 껐다 |
| `combat.tick_population(delta)` | 스폰. U3의 `spawn_timer` 밀기와 **이중 잠금**이다 |
| `_check_rifts()` | 길잡이 도중에 균열 아레나가 열리면 안 된다 |
| 잠식 스윕 | 클럭이 멈추면 잠식도 시작되지 않지만 짝을 맞춰 껐다 |
| `_tick_player_status(delta)` | 도트. "맞을 위험 0"을 무적 말고 시간 정지로도 한 번 더 건다 |

| **계속 도는 것** | 이유 |
|---|---|
| 플레이어 `_physics_process` | 스텝 ①②의 통과 조건이다 |
| **딜싸이클**(`player_cycle`) | 스텝 ③ "공격 버튼은 없습니다"를 눈으로 증명하는 **유일한 수단**. 필드에 적이 하나도 없으므로 카드가 나가도 아무 일이 안 일어난다 |
| `_refresh_interactable()` | 스텝 ⑥이 `E`를 시킨다. 이것까지 끄면 그 스텝이 죽는다 |
| HUD 갱신 · 가장자리 화살표 · `tick_spatial` · 조명 보간 | 그림이다. 멈출 이유가 없고, 클럭이 멈췄으므로 조명은 저절로 정지값에 눕는다 |

> **게이트를 `state == "playing"`으로 좁힌 이유.** 길잡이는 `playing` 서브모드라
> 보스방(`state == "boss"`)에서는 그림도 판정도 이미 꺼져 있는데, `guide_active`만
> 보고 얼리면 **보스 패턴이 붙인 도트가 안 도는 유령 상태**가 만들어진다.

### 2.3 노드축 — 제거와 동결

```
_start_guide()
  ├─ _guide_clear_threats()   잡몹 + 적 탄환 queue_free()        (보스·캠프 소속은 남긴다)
  ├─ _guide_freeze_sweep()    남은 적/탄 set_physics_process(false)
  └─ _build_guide_layer() …
_tick_guide()  0.25초마다 _guide_freeze_sweep() 재적용
_finish_guide() / _abandon_guide()
  └─ _guide_unfreeze_all()    **얼린 목록만** 정확히 되돌린다
```

* **왜 지우기까지 하는가.** `_begin_run()`이 `_maybe_start_guide()` **바로 앞줄**에서
  `_spawn_stage_starter_population()`으로 잡몹 9기를 260~720px에 뿌린다. 즉 길잡이가
  열리는 순간 플레이어는 이미 포위돼 있었다. 얼리기만 하면 "멈춘 마물 아홉 마리가
  나를 둘러싸고 있는 그림"이 되는데, 그건 위협감을 못 지운다. 런 시작이라 **잃는
  것은 0**이고, 끝나면 같은 경로로 다시 채워진다.
* **왜 적 이동만이 아니라 `_physics_process`를 통째로 끄는가.** 적의 이동 · 조준 ·
  **접촉 피해**(`contact_timer`) · 원거리 발사가 전부 `enemy._physics_process` 안에
  있다. 한 줄로 네 가지가 동시에 멎는다.
* **`is_queued_for_deletion()` 가드가 필요하다.** `queue_free()`는 프레임 끝에야
  걷히므로 방금 지운 잡몹이 아직 `combat.active_enemies`에 남아 있다. 가드가 없으면
  `guide_frozen_count()`가 **유령 열 마리를 센다**(실측 후 고쳤다).
* **되돌릴 때 전수 조회를 하지 않는다.** `guide_frozen_nodes`에 담은 것만 켠다 —
  다른 이유로 꺼져 있던 노드까지 켜 버리면 그게 새 버그다.
* **`_guide_clear_threats()`는 사본을 순회한다.** `queue_free()`가 `_exit_tree` →
  `unregister_enemy()`를 태워 원본 배열을 줄이므로, 원본을 돌면 절반만 지워진다.

### 2.4 끝나면 어떻게 깨어나는가

`_finish_guide()`가 ⓐ `_guide_unfreeze_all()` ⓑ `MODAL_RETURN_INVULN` 유예
ⓒ `combat.spawn_timer = min(현재, 1.2)`를 한다. 필드는 **한 기씩** 상한까지
다시 찬다(9기가 한꺼번에 서 있는 것보다 튜토리얼 직후에는 이 완만한 복귀가 낫다).
1회성 페이드(`GUIDE_FADE`)와 배너 한 줄은 U3 그대로 — **트윈 루프 0**.

### 2.5 실창 관찰 (재현 가능)

`--capture-guide`가 길잡이를 켠 뒤 **2.35초를 그냥 흘려 보내고** 한 줄을 찍는다:

```
GUIDE_FREEZE_OBSERVED field_before=10 field_now=0 cleared=10 frozen=0 phase_drift=0.000 invuln=1.20
```

`phase_drift=0.000` = 그 2.35초 동안 스테이지 클럭이 **한 틱도 안 돌았다**.
캡처 4컷 전부 필드에 마물이 **0기**다 — 컷에 마물이 걸어 다니면 그것이 곧 회귀 신호다.

## 3. 온보딩 다이어트 — 전후 수치

측정법: 페이지 오버레이 아래 모든 `Label`을 훑어 두 글자 이상인 것의 글자 수를 더한다
(X2가 편집 화면에 세운 `edit_prose` 계약의 온보딩 판). `test_runner._onboarding_census()`.

| | 이전 | **X4** | |
|---|---:|---:|---|
| 1페이지 | 329 | **261** | −20.7 % |
| 2페이지 | 451 | **312** | −30.8 % |
| 3페이지 | 458 | **318** | −30.6 % |
| 4페이지 | 560 | **306** | **−45.4 %** |
| **총합** | **1,798** | **1,197** | **−33.4 %** |
| 페이지 최대 | 560 | **318** | −43.2 % |
| 가장 긴 한 줄 | **59자** | **31자** | −47.5 % |
| 페이지당 규칙 줄 | 2·3·3·3 | **2·2·2·2** | |

가장 길던 한 줄(59자)은 4페이지 등급 설명문이었다:
`"기한은 없습니다. 총 13일 이하면 S · 17일 이하 A · 23일 이하 B — 빨리 넘을수록 높습니다."`
→ `"기한 없음 · 13일 S · 17일 A · 23일 B"`. **S < A < B 순서가 "빨리 넘을수록"을 이미 말한다.**

### 3.1 페이지별 규칙 줄 (전문)

| | 이전 | X4 |
|---|---|---|
| **1** | 공격 버튼은 없습니다. 무엇을 언제 쓸지는 5칸 딜싸이클이 정합니다. / 외울 필요는 없습니다 — 필드에 들어가면 길잡이가 하나씩 짚어 줍니다. | **공격 버튼이 없습니다. 카드가 알아서 나갑니다.** / **지금 외우지 마세요. 필드에서 다시 알려 줍니다.** |
| **2** | 바늘은 1 → 5로 흐르지만 각인이 터지면 되감기·도약·재실행으로 튑니다. / 각인이 발동할 때마다 과열이 1 오릅니다… / 한 바퀴가 끝나면 그동안 쌓인 RELOAD 빚만큼… | **바늘이 선 칸의 카드가 저절로 나갑니다.** / **한 바퀴를 돌면 쌓인 만큼 쉬었다 다시 돕니다.** |
| **3** | 각인을 고른 뒤 "강화할 칸"을 고릅니다… / 고르지 않은 각인 2개는 사라지지 않고… (2개당 1). / 한 칸에 몰아 넣으면 과밀 페널티로… | **각인을 고르고, 넣을 「칸」을 고릅니다.** / **고르지 않은 2개는 마왕이 가져갑니다.** |
| **4** | 1관문의 하루는 낮 72초 + 밤 45초입니다… / 주기가 끝날 때마다 체류가 1 오릅니다… / 체류가 임계를 넘으면 잠식이… | **오래 머물면 「체류」가 올라 세계가 강해집니다.** / **목적지가 화면 밖일 때만 화살표가 뜹니다.** |

지운 조건·숫자는 **버린 게 아니라 도식으로 내려갔다** — 낮/밤 초는 4페이지 상단 띠,
과밀은 3페이지 왼쪽 상자, 과열↔RELOAD는 2페이지 하단 칩, 잠식·강림은 4페이지 세 칩.

### 3.2 「빚」을 어떻게 쉬운 말로 바꿨나

지울 수는 없었다 — HUD 툴팁이 「빚 N.NN초」라고 쓰고 편집 화면 요약도 같은 낱말을 쓴다.
지우면 **처음 보는 낱말**이 게임 안에 남는다. 그래서 **쉬운 말로 먼저 가르치고
이름을 뒤에 붙였다**(2페이지 하단 칩):

```
이전  5칸을 다 지나면 RELOAD — 그동안 쌓인 "빚"만큼 쉰다
      과열이 높을수록 피해도 크지만 RELOAD도 함께 길어진다
X4    한 바퀴를 다 돌면 쉬는 시간 = RELOAD
      쌓인 쉬는 시간이 「빚」 · 과열이 높으면 더 길어집니다
```

### 3.3 도식에 **더한** 것 (다이어트지만 그림은 늘렸다)

| 페이지 | 무엇 | 왜 |
|---|---|---|
| 1 | 키 목록 **넷째 줄** — `마우스` 키캡 + 「자세히 보기 / 숫자 위에 올리면 설명이 뜹니다」 | X3 §11.2 ① — HUD 툴팁 13종(X3)과 편집 화면 툴팁(X2)을 **한 문장이 동시에 연다**. 줄 간격 84 → 68로 좁혀 넷이 규칙 구분선 위에 들어온다 |
| 2 | 바늘 캡션 「바늘 · **지속시간** 동안 실행」 | X1이 넘긴 정의. 바늘이 활성 칸 위에 서 있으므로 **위치가 곧 설명**이다 — 새 줄 0개 |
| 3 | **각인 핍이 박힌 미니 칸**(칸 3 · 노란 핍 2/3) | X2 §7.4 ③이 지목한 가장 약한 고리. 편집 화면·HUD의 6×4px 각인 핍이 무엇인지 어디서도 안 가르쳤다 |
| 4 | (없음 — 화살표 규약은 글로만 있다 · §7 참조) | |

### 3.4 공용 껍데기에서 깎은 것

푸터 안내가 **두 줄 → 한 줄**이다. `"숫자 칸을 눌러 원하는 페이지로 바로 이동"`(22자)은
지웠다 — 스파인 위의 숫자 버튼 넷이 이미 눌러 보라고 말하는 기하다. **네 페이지 전부**에
붙어 있던 줄이라 이 한 줄이 88자다.

## 7. 남은 문제 · 다음 웨이브가 알아야 할 것

### 7.1 지금 알고 있는 약한 고리

1. **4페이지 화살표 규약은 글로만 있다.** 「목적지가 화면 밖일 때만 화살표가 뜹니다」
   옆에 그림이 없다. 4페이지 도식은 이미 꽉 차 있고(낮밤 띠 · 5관문 타임라인 · 등급
   줄 · 3칩) 규칙 구분선(y 336)까지 34px밖에 안 남는다. **화면 테두리에 화살촉이
   붙은 미니 픽토그램 하나**가 들어갈 자리를 만들려면 3칩을 두 칩으로 줄여야 한다.
2. **길잡이가 끝난 뒤 필드가 한동안 비어 있다.** `spawn_timer` 1.2초부터 한 기씩
   차므로 상한까지 20초쯤 걸린다. 튜토리얼 직후로는 오히려 친절하다고 판단했지만,
   "끝나자마자 세계가 살아나는" 연출을 원하면 `_finish_guide()`에서
   `_spawn_stage_starter_population()`을 한 번 더 부르면 된다(RNG 스트림을 한 번 더
   소비하므로 `--guide-test` 뒤쪽 단언에 영향이 없는지 확인할 것).
3. **길잡이를 켠 채로 방치하면 세계가 무기한 멈춘다.** 모든 스텝에 SPACE/ESC 탈출이
   있으므로 갇히지는 않지만, "N분 지나면 자동 종료" 같은 안전장치는 없다.
4. **온보딩에 스크린샷이 없다.** 도식은 전부 절차적 도형이라 실제 화면과 1:1이
   아니다. 예: 2페이지 5칸은 168×104인데 실전 미니 스트립 칸은 52×52다(X3).
   "온보딩에서 본 그림 = 필드에서 보는 그림"을 원하면 그 기하를 맞춰야 한다.

### 7.2 이 세 파일을 다시 만질 사람에게

* **상시 문장을 하나 늘리기 전에 `--guide-test`의 `onb_peak`을 볼 것.** 상한
  360자/32자/2줄은 장식이 아니라 이 화면이 지켜야 할 계약이다(X2의 `edit_prose`,
  X3의 `hud_block_pct`와 같은 종류). 넘기려면 다른 하나를 도식으로 내려보내야 한다.
* **길잡이 중에 도는 코드를 늘릴 때는 `world_running`을 먼저 볼 것.** `_process`의
  `playing` 구역에 새 틱을 넣으면 기본값은 "길잡이 중에도 돈다"이다. 세계 시간에
  속하는 것이면 게이트 안에 넣을 것.
* **적이 아닌 새 위협(함정·환경 피해·낙하물)을 만든다면** `_guide_freeze_sweep()`에
  그 노드 종류를 더해야 한다. 지금 이 함수가 아는 것은 `DebtEnemy`와 `EnemyBullet`
  둘뿐이고, `--guide-test freeze` ⓒ(실제 물리 프레임에서 0px)가 그것을 잡아 준다.
* **`_guide_clear_threats()`는 보스·캠프 소속을 남긴다.** 지금은 길잡이가 런 시작에만
  열려서 그런 적이 존재하지 않지만, 길잡이를 다른 시점에 열 수 있게 만들면 그때는
  "남겨서 얼린 적"이 실제로 화면에 서 있게 된다 — 그 그림이 괜찮은지 다시 볼 것.
