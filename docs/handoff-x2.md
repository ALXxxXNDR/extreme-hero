## 0. 한 문장

**ESC 편집 화면에서 상시로 읽어야 하던 문장 33줄을 0줄로 만들고, 그 문장들을 하나도

| **화면에 남은 문장(2자 이상 라벨)** | **60+** | **7** |

과밀 칸의 `+N`. 캡처 덱(5칸 다 찬 상태)에서 최대 9개다.
칸 번호 `1~5` · 원소 마크 `화/빙/뇌/유` · `▶` · `◀`는 **1글자 기호**라 세지 않는다.

## 4. 툴팁 시스템 사양 (`ui_kit.gd` §6 — 공용 신설)

### 4.1 API

```gdscript
var layer := UIKit.make_tooltip_layer(overlay)      # 화면당 1장 · 맨 마지막에 붙일 것
UIKit.attach_tooltip(target, layer, {
    "title": "화염장",                # 강조색으로 굵게
    "accent": Color,                  # 제목 색 (원소색·희귀도색을 그대로 넘긴다)
    "rows": [["지속", "1.20초", CYAN], ["RELOAD", "0.35초"]],   # 2열 표 (색 선택)
    "body": "한 문장 설명 — 330px에서 자동 줄바꿈"
})
UIKit.tooltip_focus(layer, control)   # 키보드 포커스 경로(같은 지연)
UIKit.tooltip_force(layer, control)   # 지연 0 — **캡처 전용**
UIKit.tooltip_hide(layer)
UIKit.tooltip_shown(layer) -> Control # 지금 떠 있는 툴팁의 주인(테스트용)
```

### 4.2 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 지연 | `TOOLTIP_DELAY = 0.25`s | 사용자 지정 |
| 등장 | 알파 0 → 1, `0.12`s **1회성** 트윈 | `set_loops()` 0건(ui-style-v3 §12) |
| 사라짐 | 즉시 `queue_free` | 페이드아웃을 두면 이동 중 잔상이 겹친다 |
| 톤 | `ABYSS · Role.PANEL` 고정 | 어느 화면 위에 떠도 "툴팁은 하나의 소속" |
| 폭 | 최소 210 / 본문 줄바꿈 330 | `PanelContainer + VBox`라 **내용이 크기를 정한다** |
| 위치 | 대상 아래 +10px · 넘치면 위로 뒤집고 좌우는 화면 안으로 클램프 | |
| 마우스 | 층·상자 전부 `MOUSE_FILTER_IGNORE` | 툴팁이 자기 아래 버튼을 막으면 안 된다 |
| 일시정지 | 층만 `PROCESS_MODE_ALWAYS` | 편집 화면은 트리를 멈춘 채 뜬다 — 안 그러면 지연 타이머가 안 돈다 |

### 4.3 왜 `tooltip_text`(엔진 기본)를 안 썼나

1. 지연이 **프로젝트 전역 설정 하나**뿐이라 화면별로 못 준다.
2. **키보드 포커스에서는 아예 안 뜬다.** 이 게임은 단일 포커스 키보드 경로가
   마우스와 동급 시민이라(부록 C-1) 두 입력이 다른 정보를 보면 반쪽이 된다.
3. **캡처에서 강제로 띄울 수 없다** — 호버 상태를 QA 스크린샷으로 남길 방법이 없다.
   `tooltip_force()`가 지연만 건너뛰고 나머지 경로는 사람이 호버했을 때와 **완전히 같다**.

`attach_tooltip()`은 대상의 `tooltip_text`를 빈 문자열로 지운다. 안 지우면
엔진 툴팁과 킷 툴팁이 두 겹으로 뜬다.

### 4.4 편집 화면의 호버 대상 지도 (`factory_tooltip_targets` 키)

| 키 | 대상 | 담고 있는 것(= 화면에서 지운 것) |
|---|---|---|
| `help` | `?` 칩 | 칸/각인/장비/보관함 수 · 드래그 두 갈래 · 키보드 4줄 · 규칙 4문장 |
| `summary` | 요약 칩 | 몬테카를로 지표 **7종 전부** + 과열 분포 + 대표 궤적 3개 + 표본/ms |
| `bond` | 결속 띠 + 되돌이 선 | 결속 칸수·조건·효과 · 삼각 할인 · **한 바퀴 규칙** |
| `slot{N}_handle` | 칸 손잡이 | 카드명 · 각인 수 · 속성 · "끌면 각인 동반" · `SHIFT+SPACE` |
| `slot{N}_card` | 카드 몸통 | 랭크 · 지속 · RELOAD · **피해계수** · 속성·형태 태그 · desc · "카드만" |
| `slot{N}_runes` | 각인 핍 줄 | 구 「각인 스택 상세」 패널 통째 (이름·실효확률·과밀 배율·효과) |
| `arc{N}` | 아크 꼭대기 핍 | 구 아크 라벨(`이름 42%`) + 바늘 이동 + 흐름 설명 |
| `inventory` | 가방 글리프 칩 | 보유 장수 · 레일/장비로 보내는 법 · 빼는 법 |
| `inventory_empty` | 첫 자리표시 타일 | 구 빈 상태 2문장 |
| `inv{N}` | 보관함 타일 | 카드 상세(스킬) / 부위·적용·효과(아이템) |
| `equipment` | 열쇠 글리프 칩 | 장비 x/4 · 넣는 법 · 빼는 법 · "레일 밖" 설명 |
| `equip{N}` | 부위 타일 | 부위 이름 · 등급 · 적용 범위 · 효과 · desc |
| `close` | 닫기 버튼 | `ESC` |

**정보 손실 0.** `--v4-test edit_minimal` ⓒⓔ가 등록 여부와 각인 무손실을 단언한다.

## 5. 드래그 UX 최종안 — **모드 제거**

### 5.1 무엇을 지웠나

| 지운 것 | 대체 |
|---|---|
| 모드 바 버튼 2개 (`[1] 카드 이동 / 교체`, `[2] 칸 위치 교환`) | **집는 대상**이 조작을 정한다 |
| 모드별 프레임 뒤집기(칸 전체가 RUNE 프레임이 됨) | 프레임은 항상 **그 칸의 카드**를 말한다(+ 원소 틴트) |
| 키 `M` · `1` · `2` | `SPACE`(카드) / `SHIFT+SPACE`(칸 통째) |
| 모드 안내 문단 · 집기 상태줄 | 집은 순간 배너 1회 + 흰 이중 링 |

`factory_edit_mode` **변수는 남겼다.** 이제 화면 모드가 아니라 "키보드로 집은 것이
어느 쪽이었나"만 기억한다. `_apply_editor_gesture()`가 그 값을 읽는 계약은 무변경.

### 5.2 자동 판별의 물리

칸(196×204)이 두 조각으로 갈려 있다.

```
┌──────────────────────┐  ← 카드 프레임(SKILL/ITEM) + 원소색 틴트
│ ①  ≡grip≡        화 │  y 14~42   손잡이 = "칸 통째"  gesture "slot"
├──────────────────────┤
│      [ 아이콘 80 ]    │  y 46~158  카드 몸통 = "카드만" gesture "card"
│        화염장         │
├──────────────────────┤
│ ▬▬▬▬▬▬  ▬▬▬▬▬▬      │  y 162~172 지속(청)·RELOAD(주) 막대 — 숫자 없음
│ ●●●  +1              │  y 174~186 각인 핍(희귀도색)
└──────────────────────┘
```

집는 순간 **고스트가 다르다**:
`FactoryDragButton.ghost_source`를 손잡이에만 칸으로 걸어 뒀으므로
카드를 집으면 카드 한 장이, 손잡이를 집으면 **칸 전체**가 마우스를 따라온다.
이것이 모드 안내 문단을 대체하는 핵심 장치다 — 규칙을 읽는 대신 **든 것을 본다**.

### 5.3 드롭 하이라이트

`FactoryDragButton`에 `drop_hint: Callable` · `drop_hint_host: Control`을 더했다.
`NOTIFICATION_DRAG_BEGIN`에서 모든 후보가 `gui_get_drag_data()`를 읽고 스스로
받을 수 있는지 답한다 — 받을 수 있으면 원래 밝기, 없으면 `0.46,0.49,0.58,0.72`로 죽는다.
`DRAG_END`에서 원래 `modulate`로 복원한다(`_update_factory_focus`가 칠한 값을 안 잃는다).

판정은 `_edit_drop_allowed(source, target)` 한 곳이고 `_on_factory_card_dropped`의
분기와 **같은 규칙**이다 — 켜진 자리는 반드시 성립하고, 꺼진 자리에 놓으면
아무것도 안 옮기고 기존 배너가 뜬다(튕김).

| 출발 → 도착 | 허용 |
|---|---|
| 레일 → 레일(다른 칸) | ✔ (제스처는 페이로드가 나른다) |
| 레일 → 보관함(타일·자리표시) | ✔ |
| 보관함 스킬 → 레일 | ✔ |
| 보관함 아이템 → 레일 | ✘ 배너 |
| 보관함 아이템 → 장비 부위 | ✔ **X2 신설**(예전엔 클릭 배치만) |
| 보관함 스킬 → 장비 | ✘ 배너 |
| 보관함 → 보관함(다른 인덱스) | ✔ |
| 장비 → 어디든 | ✘ (장비는 드롭 **받기만** 한다. 빼기는 클릭) |

### 5.4 불변 (한 줄도 안 건드렸다)

`FactoryDeck.move_card` / `swap_slots` / `place_card` / `equip` / `clear_slot`의
의미, `_on_factory_card_dropped`의 다섯 분기, `_apply_editor_gesture`, 미리보기
계산(`_factory_preview_summary` · `RuneEngine.simulate_cycle` 공유), 저장 스키마.

## 6. 원소 색 언어 — X1 규약 그대로 재사용

`_element_color()`를 부르기만 했다. **새 색표 0개**(handoff-x1 §3의 지시).
층 구성도 X1과 같고, 강도만 캡처 3회로 다시 잡았다:

| 층 | 강도 | X2 적용 자리 | 왜 그 값인가 |
|---|---|---|---|
| 카드 프레임 `modulate_color` | `WHITE.lerp(색, 0.55)` | 칸 프레임 · 보관함 타일 | X1 실측값 승계 |
| 칸 덧칠 | `0.16` | 칸 안쪽 168×172 | 칩 사이 틈·막대·핍 구역 몫 |
| 손잡이 덧칠 | `0.20` | 손잡이 띠 안쪽 | 숫자·마크 대비를 안 깎는 상한 |
| **아이콘 블록 덧칠** | **`0.34`** | 아이콘 96×84 사각형 | 사용자가 말한 "블록색". **색의 주역** |

### 6.1 캡처 3회로 잡은 것 (X2가 새로 밟은 함정)

1. **1차 — 덧칠이 아예 안 보였다.** 칸 층에만 깔았는데 손잡이 띠와 카드 몸통이
   **불투명한 킷 칩**이라 그 위를 통째로 덮었다. 화·타·뇌 넉 장이 전부 프레임 주황
   하나로 뭉쳐 나왔다. → 두 조각 **안쪽에** 각각 한 겹씩 더 깔았다.
2. **2차 — 이번엔 글자가 죽었다.** 카드 몸통 **전체**를 0.30으로 칠했더니 이름 줄까지
   뿌예졌다. 무채 원소인 타(打)`STONE_LIGHT`에서 특히 심했다(우유를 부은 것처럼 됐다).
   → X1이 왜 "본문 판 0.14 / **아이콘 블록** 0.34" 둘로 갈라 놨는지가 여기서 드러난다.
   **아이콘이 앉는 사각형만** 칠하고 글자 자리는 어두운 채로 뒀다.
3. **3차 — 캡처 덱이 색을 증명하지 못했다.** 구 덱이 화·타·뇌·타(따뜻한 색 + 무채)라
   한 장에서 "속성 = 색"이 갈리는지 볼 수 없었다. → `_setup_rail_capture_deck()`를
   **화·빙·뇌·유 네 계**로 바꿨다(`frost_ring`·`gravity_well`). X1이 `--capture-choice`에서
   "원소가 서로 다른 두 장이 나올 때까지 다시 뽑는" 장치를 둔 것과 같은 이유다.

## 8. 밟은 함정

1. **`EDIT_CARD_SIZE`·`EDIT_SLOT_PAD`·`EDIT_SLOT_CARD_RECT`·`EDIT_SLOT_RUNE_Y`·
   `EDIT_SLOT_HEADER_H`는 편집 화면 전용이 아니다.** `_build_preview_slot()`
   (마왕 프리뷰 · 결과 화면 · W10 소유)이 **같은 상수를 공유**한다. 칸 높이를
   150 → 204로 올리려고 이 상수를 고치면 X2 범위 밖 화면 두 개가 같이 늘어난다.
   → 편집 전용 기하를 `EDIT_SLOT_*`(SIZE/HANDLE_RECT/BODY_RECT/METER_Y/PIP_Y/ICON)
   새 이름으로 따로 뒀다. **합치지 말 것.**
2. **`_build_edit_flow_arcs()`도 세 화면이 공유한다**(편집 · 마왕 프리뷰 ×2).
   라벨을 지우면 프리뷰에서도 지워진다 → `minimal: bool = false` 선택 인자를
   맨 끝에 붙였고 편집 화면만 `true`를 넘긴다. 기본값 false라 나머지는 무변경.
3. **툴팁 층은 반드시 맨 마지막에 붙인다.** 먼저 붙이면 카드·칸이 툴팁을 덮는다.
   그래서 배선이 2단계다 — 조립 중에는 `_edit_tip()`이 내용만 meta에 매달고,
   층이 생긴 뒤 `_bind_edit_tooltips()`가 한 번에 시그널을 잇는다.
4. **`get_meta(name, default)`는 이 빌드에서 기본값을 줘도 ERROR 줄을 찍는다**
   (handoff-u2 §5.3 #1). `_bind_edit_tooltips()`는 `has_meta`로 먼저 거른다.
5. **`Array[Node] = [x] if cond else []`는 런타임 타입 오류다.** 삼항의 결과가
   untyped `Array`라 대입에서 죽는다(테스트 1차 실행이 여기서 SCRIPT ERROR).
   조건문으로 풀어 쓸 것.
6. **`_kit_panel()`은 `MOUSE_FILTER_IGNORE`로 만든다.** 툴팁을 걸려면 마우스를
   받아야 하므로 `attach_tooltip()`이 IGNORE인 대상을 **PASS로 올린다**
   (STOP으로 올리면 그 아래 카드 버튼이 클릭을 못 받는다).
7. `grip`은 **글리프가 아니라 포인터 아틀라스**에 있다(`ui-kit-pointers.png`).
   `_kit_glyph()`로는 안 나온다 → `_kit_pointer()`를 새로 뒀다(`_kit_glyph`와
   같은 규약 · 확장 모드를 먼저 끄는 함정도 같다).
8. **불투명한 칩이 알파 덧칠을 덮는다** — §6.1 ①②. X1의 세 층 구조를 "대충 비슷하게"
   옮기면 색이 안 나오거나 글자가 죽는다. 강도가 아니라 **어느 층 위에 얹는가**가 문제다.

## 9. X3 · X4가 알아야 할 것

### 공통 — 툴팁은 이제 프로젝트 자산이다

* `UIKit.make_tooltip_layer` / `attach_tooltip` / `tooltip_focus` / `tooltip_force`는
  **어느 화면에서도 쓸 수 있다.** 편집 화면에만 배선돼 있을 뿐 편집 전용이 아니다.
* 툴팁을 쓰는 화면은 층을 **오버레이의 마지막 자식**으로 만들고, 화면을 다시
  조립하면 층 참조를 `null`로 끊을 것(층은 오버레이와 함께 죽는다).
* 새 화면에서 문장을 지우고 싶으면 **먼저 갈 곳(툴팁 rows/body)을 정하고** 지울 것.
  정보 손실 0이 X2가 통과한 기준이고 테스트가 그것을 단언한다.

### X3 (HUD 탈블록 · 나침반 → 화면 가장자리 화살표)

* **X2는 필드 HUD를 한 줄도 건드리지 않았다.** `_hud_panel()`·`_update_cycle_rail()`·
  레일 슬롯 렌더러 전부 무접촉이다.
* HUD 레일의 원소 마크는 여전히 **글자만** 있고 색이 없다(X1이 남긴 숙제 그대로).
  이제 편집 화면과 레벨업 모달 **둘 다** `_element_color()`로 물들었으므로,
  HUD까지 칠하면 "속성 = 색"이 세 화면에서 한 언어가 된다.
* 미니 딜싸이클 모드를 만든다면 편집 화면의 **칸 기하를 재사용하지 말 것** —
  `EDIT_SLOT_*`는 1,240px 패널 전용이다. HUD는 `RAIL_*` 계열이 따로 있다.
* 필드에서 툴팁을 쓰려면 층의 `process_mode`를 그대로 `ALWAYS`로 둘 것.
  일시정지 여부와 무관하게 같은 지연이 나온다.

### X4 (온보딩 텍스트 다이어트)

* **X2가 남긴 가장 약한 고리는 "각인"이다**(§7.4 ③). 칸 아래 색 핍이 각인이라는
  것, 그것이 카드가 아니라 **칸**에 붙는다는 것 — 이 둘은 지금 호버로만 배운다.
  온보딩이 한 컷으로 가르치면 편집 화면이 완결된다.
* 온보딩에서 **「카드 이동 모드」·「칸 교환 모드」·`M` 키**를 언급하는 곳이 있으면
  전부 거짓이다. 지금 규약은 "카드 그림을 끈다 / 칸 손잡이를 끈다"와
  "SPACE / SHIFT+SPACE" 둘뿐이다.
* U3 스포트라이트 길잡이의 ESC 스텝이 편집 화면의 **어느 사각형**을 짚는지
  다시 볼 것 — 좌표가 전부 바뀌었다(레일 `192 → 134`, 보관함 `448 → 380`,
  미리보기 패널·각인 패널은 **아예 없어졌다**).
* X1이 넘긴 두 정의("지속시간 = 카드가 행동하는 시간 / RELOAD = 레일 한 바퀴 뒤
  합산되는 대기시간")는 X2도 화면에 두지 않았다. 지금은 요약 칩 호버와 카드 호버
  두 곳에 숫자로만 있다 — **정의를 말로 가르치는 자리는 여전히 X4 몫이다.**
* `?` 툴팁이 편집 화면 규칙 전부를 이미 담고 있다. 온보딩은 그것을 **반복하지 말고**
  "ESC를 누르면 여기서 다 바꿀 수 있고, 모르면 ? 에 마우스를 올려라"까지만 하면 된다.

### 편집 화면을 다시 만질 사람에게

* `factory_edit_mode`를 화면 상태로 되돌리지 말 것. 지금 이 변수를 읽는 곳은
  `_apply_editor_gesture()` 하나이고, 쓰는 곳은 `_editor_slot_pressed(slot, gesture)`
  하나다. 모드 UI를 되살리면 사용자 피드백 ⑤를 정면으로 어긴다.
* 상시 라벨을 하나 더 넣고 싶으면 먼저 `--v4-test`의 `text_labels <= 16`을 볼 것.
  그 상한은 장식이 아니라 **이 화면이 지켜야 할 계약**이다. 넘기려면 다른 하나를
  호버로 내려보내야 한다.
* 삭제한 함수: `_build_edit_header` · `_build_edit_mode_bar` · `_build_edit_preview_panel`
  · `_build_edit_rune_panel` · `_paint_edit_rune_detail` · `_build_edit_footer` ·
  `_set_factory_edit_mode` · `_toggle_factory_edit_mode` · `_edit_slot_center_x`.
  삭제한 상수: `EDIT_MODE_BAR_Y` · `EDIT_PREVIEW_RECT` · `EDIT_RUNE_RECT`.
  삭제한 변수: `factory_rune_panel`. **원본은 `docs/v1-archive/`와 이 문서 §2 표에 있다.**
* `DealCardLibrary.combat_tags()`는 **여전히 살아 있다** — X2가 편집 화면에서 뺐지만
  `_build_pending_card_summary()`(공장 place 모드)가 아직 유일한 호출부다.
  그 화면을 손대는 사람이 마지막 호출부를 지우면 그때 함수를 지우면 된다.
* `_factory_card_button(card, size, prefix, **inner**)`의 네 번째 인자가
  **호출부 0이 됐다**(편집 화면 5칸이 유일한 사용처였다). 편집 화면은 이제 자기
  골격(`_build_edit_slot_body`)을 쓴다. 남겨 뒀으니 쓸 데가 있으면 쓰고, 없으면 지워도 된다.
* `_edit_mode_color()`는 살아 있지만 이제 **집었을 때 배너 색 한 곳**만 쓴다.
