## 0. 한 문장

**필드 HUD를 덮고 있던 불투명한 판 다섯 장(신상·스테이지·나침반·마왕 고스트·딜싸이클

## 2. **필드 가시 면적 — 전후 수치**

측정법: 1280×720을 4px 격자로 래스터화해 **합집합** 넓이를 센다(사각형을 더하면
겹친 자리가 두 번 세어진다). `test_runner._hud_coverage()`가 그 자다.

* **block** = 불투명한 판. Panel 9-slice + 알파 0.5 이상 ColorRect.
* **ink** = 눈에 보이는 HUD 요소 전부의 바운딩 박스(글자·아이콘·얇은 게이지 포함).

### 2.1 상시(필드 플레이 중)

|---|---:|---:|---:|
| block px | 292,488 | **30,912** | **9.5× 감소** |
| block % | **31.74 %** | **3.35 %** | |
| ink % | 31.74 %(전부 판 안이었다) | **8.54 %**(캡처 덱) / 6.88 %(빈 덱) | 3.7× 감소 |
| **필드가 보이는 면적** | 68.3 % | **96.7 %** | +28.4 %p |

와 `--cycle-test`의 `hud_block_pct=3.32 hud_ink_pct=6.88`(스테이지 1 · 균열 없음).

## 4. 화살표 내비 사양

### 4.1 규약 다섯 줄

| # | 규약 |
|---|---|
| ① | 대상이 화면 안 `NAV_HIDE_MARGIN`(56px) **안쪽**에 들어오면 화살표가 사라진다 |
| ② | 대상 방향으로 링(`NAV_RING` = x 44\~1236 · y 96\~604) 위 한 점에 마커 **중심**이 붙는다 |
| ③ | 화살촉 + 대상 글리프 + 거리(m) 세 조각. **전부 정적**이다(깜빡임 0 · 트윈 0) |
| ④ | 색과 글리프가 대상을 구분한다 |
| ⑤ | 성·캠프 내부, 보스전, 필드 밖에서는 층 전체가 꺼진다 |

### 4.2 대상 4종

| key | 이름 | 글리프(절차적) | 색 | 출처 |
|---|---|---|---|---|
| `castle` | 성 | 집(몸통 + 총안 3 + 어두운 문) | `YELLOW` | 구 나침반 2줄 색 승계 |
| `camp` | 캠프 | 천막(삼각 + 어두운 입구) | `GREEN` | 성 안 캠프 표기색 승계 |
| `boss_gate` | 보스문 | 해골(두개골 + 턱 + 눈구멍 2) | `RED` | 구 나침반 1줄 색 승계 |
| `rift` | 균열 | 갈라진 금(두꺼운 지그재그) | `MAGENTA` | 구 나침반 3줄 색 승계 |

### 4.3 왜 킷 글리프를 안 썼나 (`build_assets_ui` 확장을 안 한 이유)

1. 킷 글리프 16종에 집·천막·해골·균열이 **없다**. 넷을 넣으면 시트가 2행 → 3행이 되어
   `ui-kit-glyphs.png`를 다시 굽고 `UIKit.GLYPH_INDEX` 계약을 건드려야 한다.
   그 시트는 **다른 화면 전부**가 쓴다 — X3 범위 밖의 위험이다.
2. **화살촉은 임의 각도로 돌아야 한다.** 킷 포인터 아틀라스(`pointer_left/right/up/down`)는
   4방향뿐이라 대각선에서 방향이 거짓말을 한다. `EdgeMarker._draw()`가 `Vector2.from_angle()`로
   삼각형을 직접 그린다.
3. 결정성은 그대로다 — 그리는 코드가 결정적이고 굽는 자산이 늘지 않는다.

### 4.4 판독성 장치

| 조각 | 처방 |
|---|---|
| 화살촉 | 근사흑 `(0.03,0.05,0.09,0.92)` 폴리곤을 1.34배로 **먼저** 깔고 그 위에 색을 얹는다 |
| 글리프 | 뒤에 반지름 12 **로컬 스크림**(같은 색 알파 0.72) 원 한 장. 판이 아니라 점이다 |
| 거리 | `draw_string_outline(4px)` → `draw_string`. 흐름 배너가 W12에서 받은 것과 같은 처방 |
| 색 | `_hud_ink()`를 통과시켜 명도 하한 0.66을 보장(색상은 안 건드린다) |

### 4.5 좌표 계약

* 월드 → 화면은 **카메라 하나만** 지난다: `get_viewport().get_canvas_transform() * 월드좌표`.
  `hud`가 화면 전체 앵커라 로컬 = 전역이므로 그 결과를 그대로 쓴다(헤드리스도 같다).
* 링은 **사각형**이다(`_nav_ring_point()`). 원형 링은 네 귀퉁이를 못 써서
  대각선 목적지 넷이 좁은 호에 몰린다.
* 갱신은 `_process`에서 **매 프레임**이다. 10Hz로 돌리면 이동 중 테두리에서 눈에 띄게 끊긴다.
  `_update_hud()`가 10Hz로 한 번 더 부르는 것은 거리 문자열까지 맞추는 멱등 이중 갱신이다.

## 5. 미니모드 구성

```
로컬 좌표(스트립 380×74)
  y  1~10   ▲ 바늘 14×9          — 실행 중인 칸 위. 보간 없음(위치 점프 = 정보)
  y 12~64   [과열 8핍 20×48] [칸 5개 52×52 · 간격 10] [RELOAD 다이얼 44]
  y 66~70   빚 게이지 300×4
가로 증명: 2 |20| 8 |30 … 330 (52×5 + 10×4 = 300)| 2 |44| 4 = 380
```

칸 하나(52×52) 안쪽 — **Label 0개**:

```
y  4~40  아이콘 36×36 (원소색)
y 42~45  진행 바 44×3  (이 칸이 실행 중일 때만 찬다)
y 46~50  각인 핍 3개(6×4 · 희귀도색) + 과밀 점 3×4
프레임    킷 CELL 9-slice × 원소색 곱 틴트
```

| 구 요소 | X3 |
|---|---|
| 과열 온도계 46×118 (8단 + "과열" 캡션) | 과열 **8핍** 20×48. 단수·색(청→금→적)·유령 미달 구간 전부 유지 |
| 정보 열 126×132 (수치 3줄 + 다이얼 62) | 다이얼 **44**만 남았다. 수치 3줄은 툴팁 |
| 각인 배지 3핍 + `+N` 글자 | 3핍 + **과밀 점**(글자 없음) |
| 바늘 20×12 노랑 고정 | 14×9. 과열이 관문을 넘으면 **과열색으로 갈아입는다** — 온도계를 안 봐도 위험이 읽힌다 |
| 밴드 머리말 + 빚 줄 + 상태 줄 | 전부 `rail` 툴팁 |

### 5.1 원소색이 세 화면에서 한 언어가 됐다

`_rail_slot_color(card)` = `_element_color(_card_element(card))`.
v1은 `_factory_card_color()`(카드마다 따로 박힌 `color` 키)를 썼는데 그 값은 원소와
무관해서 같은 빙(氷) 카드 넷이 서로 다른 색으로 나왔다(X1 §3이 실측한 문제).
X1(레벨업) · X2(ESC 편집) · **X3(필드 HUD + 마왕 고스트)** 가 이제 같은 표를 본다.
**새 색표 0개** — `ELEMENT_COLOR` 하나만 존재한다.

칸 틴트 강도는 `RAIL_SLOT_TINT_MIX_IDLE` **0.22 → 0.42**로 올렸다. 칸이 152×104 →
52×52로 줄어 원소색을 나르는 면적이 프레임 테두리뿐인데, 옛 값으로는 화·빙·뇌·유
넉 장이 캡처에서 전부 같은 어두운 회녹으로 뭉쳤다(실측). 활성/비활성은 **밝기**로
갈리므로(활성은 흰색 기준 lerp) 채도를 올려도 안 섞인다.

## 6. 판독성 확보 수단 (판을 걷고도 읽히는 이유)

| 수단 | 어디에 | 근거 |
|---|---|---|
| `_label()` 외곽선 2/3px | HUD 글자 전부 | U2가 정한 값 그대로(§3 ui-style-v3) |
| 외곽선 **6px** | 상호작용 안내 · 흐름 배너 | W12가 흐름 배너에서 검증한 처방을 상호작용 칩에도 적용 |

| 반투명 트랙(α 0.72~0.82) | 체력·경험·낮밤·체류·빚·칸 진행 | 게이지의 "빈 쪽"이 보여야 길이가 읽힌다. 필드는 비친다 |
| `_hud_ink()` 명도 하한 0.66 | 의미색 글자·화살표 색 | U3가 킷 판 위에서 쓰던 것을 **필드 위**로 확장 |
| 킷 CELL 9-slice | 레일 칸 5 · 고스트 칸 5 | 아이콘 뒤 배경이 필요한 유일한 자리. 이 10개가 남은 `block`의 59% |

### 6.1 자가 기준 — 5스테이지 밤 컷

`hud-x3-stage5-night.png`(CanvasModulate `#2f2f52` + 안개 0.24 + 비네트 0.55)에서 확인:

| 볼 것 | 판정 |
|---|---|
| 체력 바 + 「120 / 120」 | **읽힌다** (초록 채움 + 흰 숫자 + 외곽선) |
| 바늘 | **읽힌다** (과열 6 → 주황 삼각형이 칸 위에서 튄다) |
| 가장자리 화살표 2종(균열 100m · 보스문 402m) | **읽힌다** (글리프·색·거리 전부) |
| 미니 스트립 원소색 | **읽힌다** (화 주황 · 빙 청 · 뇌 황이 갈린다) |
| 스테이지 줄 · 잠식 경고 | **읽힌다** |

### 6.2 밟은 함정

1. **`_label()`은 `clip_text = true`다.** 상자 높이가 글꼴 줄 높이보다 낮으면 말줄임이
   아니라 **글자가 위아래로 썰린다**(V11이 나침반에서 밟은 것과 같은 함정).
   17px 라벨에 20px 상자를 줬다가 첫 캡처에서 위아래가 잘렸다 → 이 파일의 라벨 상자는
   전부 **폰트 크기 + 5px 이상**으로 잡혀 있다.
2. **킷 글리프 16종 중 뒤 6종은 흰 선화가 아니다.** `heart`는 NA 원본
   (`Ui/Receptacle/IconHeart`)이라 자기 색을 갖는데, `modulate`는 곱연산이므로 붉은
   틴트를 얹으면 두 번 곱해져 밤에 새까매진다 → **흰색으로 둔다**. `coin`(index 8)은
   절차적 흰 선화라 틴트가 먹는다. 앞 10종만 색을 입힐 수 있다.
3. **핍 자리를 고정하면 빈 칸이 보인다.** 보호막 6칸 + 부활 6칸을 고정 배치했더니
   수호 3 · 부활 1에서 가운데 세 칸이 빈 채로 남아 "핍 하나가 멀리 떨어진" 그림이
   됐다(캡처 실측) → 보이는 핍만 **연속으로 다시 눕히고** 두 무리 사이만 한 칸 벌린다.
4. **캡처는 `state`를 `"preview"`로 돌려 화면을 멈춘다.** `_update_edge_nav()`는
   `state == "playing"`에서만 켜지므로 그대로 두면 **QA 컷에서 화살표가 통째로 빠진다** —
   `_capture_paint_edge_nav()`가 한 프레임만 state를 되돌려 그린다.
5. **점유 측정에 전면 앵커 층을 넣으면 100%가 나온다.** 길잡이 층·툴팁 층은
   화면 전체 Control이라 `_hud_coverage_walk()`가 **이름과 신원 둘 다로** 거른다.
   (`UIKit.make_tooltip_layer`가 `UIKitTooltips`로 이름 짓지만 X3는 `HudTooltips`로
   바꿔 달았다 — 이름만으로 거르면 샌다.)
6. **카메라는 순간이동을 안 따라간다.** 화면 좌표로 판정하는 검사(화살표 숨김)는
   `camera.reset_smoothing()` + `force_update_scroll()` + 두 프레임을 안 흘리면
   **옛 카메라 기준**으로 답한다. `test_runner._settle_camera()`가 그 자다.
7. **`MOUSE_FILTER_IGNORE` 부모는 자식의 마우스를 막지 않는다.** `hud`가 IGNORE인 채로
   `attach_tooltip()`이 대상만 PASS로 올리면 호버가 정상 동작한다(X2 §8 #6과 같은 규약).
   이 게임은 필드에서 마우스 입력을 아예 안 쓰므로 PASS가 조작을 뺏을 위험이 없다
   (`InputEventMouseButton` 처리부 **프로젝트 0건**을 확인했다).

## 7. 툴팁 지도 — "정보 손실 0"의 증명

`UIKit.make_tooltip_layer` / `attach_tooltip`(X2 신설)을 **필드에서 처음 쓴다**.
층은 `hud`의 마지막 자식이고 `PROCESS_MODE_ALWAYS`다. 내용은 `_update_hud_tooltips()`가
10Hz로 갈아 끼운다(`attach_tooltip`은 두 번 불러도 배선은 한 번, 내용만 바뀐다).

| 키 | 대상 | 담고 있는 것(= 화면에서 지운 것) |
|---|---|---|
| `vitals` | 좌상단 클러스터 | 캐릭터 이름「왕국 검사」· 체력 · **「수호 N · 부활 N」** · **「경험 N / N · 다음 선택」** · 자금 · **「필드 마물 NNN · 처치 NNN」** |

| `ghost` | 우상단 5칸 | **「마왕의 5칸」** 제목 · **「각인 N / N」** · **「받은 카드 N · 잔재 N · HP ×N」** · **칸별 카드 이름 + 각인 수**(구 숫자 배지) |
| `rail` | 미니 스트립 전체 | **「딜싸이클 · 칸 NN / NN ↺N」** · **「빚 N.NN초 · 청산 시 RELOAD N.NN초」** · **「N바퀴 · N.NN초」/「RELOAD N.NN초」/「과부하」** · 과열 |

칸 툴팁의 「랭크 · 속성」 줄로 살아남았다 — X1이 "색만으로 말하지 말 것"이라 못 박은 몫이다.

캡처가 호버를 그림으로 남기는 창구는 `_force_hud_tooltip(key)`다(지연만 건너뛰고
나머지 경로는 사람이 호버했을 때와 완전히 같다 · X2 §4.3).

## 11. X4(온보딩)가 알아야 할 것

### 11.1 온보딩 문구가 거짓말이 된 자리

* **「나침반」이라는 단어를 쓰면 안 된다.** 그런 패널은 없다. 지금 규약은
  「화면 가장자리 화살표」이고, 화살표는 **대상이 화면에 들어오면 사라진다**.
  `MILESTONE_BANNER["stage_rift_1"]`이 아직 "나침반을 따라가"라고 말한다 —
  이 문자열은 W4 소유(dwell 사건 배너)라 X3가 건드리지 않았다. **X4가 고칠 것.**
* 「오른쪽 세로 온도계」·「밴드 아래 가로 막대」 같은 위치 지시는 전부 틀렸다.
  지금은 **왼쪽** 세로 8핍 · **아래** 가로 빚 바 · **오른쪽** 원형 다이얼이다.
  (U3 길잡이 `gauge` 스텝 본문은 X3가 이미 고쳤다.)
* 「딜싸이클 밴드」가 화면 아래를 가득 채운다는 그림도 틀렸다. 380×74 스트립이다.

### 11.2 온보딩이 가르쳐야 할 새 규약 (지금 어디서도 안 가르친다)

1. **"자세한 숫자는 마우스를 올리면 나온다."** X3가 HUD 문장 33줄을 호버로 내렸고,
   ESC 편집 화면(X2)도 같은 구조다. **이 한 문장이 두 화면을 동시에 연다** —
   온보딩에서 한 번만 말하면 된다.
2. **"화살표는 목적지가 안 보일 때만 뜬다."** 사라지는 것이 고장이 아니라 규약이라는
   것을 모르면 "왜 화살표가 없어졌지?"가 된다.
3. X2가 남긴 가장 약한 고리(**각인 = 칸에 박히는 보석**)는 X3에서 더 작아졌다 —
   HUD 미니 칸의 각인 핍은 6×4px다. 온보딩 한 컷이 여전히 필요하다(X2 §9 그대로).

### 11.4 HUD를 다시 만질 사람에게

* 상시 라벨을 하나 더 넣기 전에 §3의 "상시 문장 6개"를 볼 것. 그 수가 이 화면이
