> **이 문서는 v2 대비 델타만 적는다.** v2와 같은 것은 다시 쓰지 않고 참조만 한다.
> v2 원본은 `docs/GAME_DESIGN_V2.md`(부록 C = v2 확정 결정), 현황은 `AGENTS.md`.
> **v2 부록 C와 이 문서가 충돌하면 이 문서가 우선한다.** 이 문서 내부에서는
> **부록 A(v3 확정 결정)가 본문보다 우선**한다.
>
> 작성 2026-08-09 · 근거: v2 코드 전수 조사(파일·줄 번호는 §9에 인용) · 에셋 실측
> **수치의 최종 진실은 여전히 코드다**(`core/tuning.gd` + 라이브러리). 이 문서의 숫자는
> **착수 초기값**이며 확정은 `balance_probe.gd` 확장판이 한다.

## 0. 무엇이 바뀌지 않는가 (먼저 못 박는다)

아래는 v2에서 그대로 간다. 어떤 웨이브도 건드리지 않는다.

1. **5칸 무스크롤 딜싸이클 + 바늘 + 과열 + 빚 RELOAD.** `RuneEngine.simulate_cycle()`이
   궤적의 유일한 진실 원천이라는 계약 포함.
2. **각인은 칸에 붙는다.** 중복 강화 4겹 감쇠, 칸 교환(`swap_slots`), 24종 카탈로그.
3. **미선택 카드·각인 조각은 전부 마왕에게 간다.** 마왕 5칸은 그것으로 조립된다.
4. **트윈 루프 애니메이션 금지.** 강조는 `delta` 감쇠 float.
5. **WFC 무한 맵 알고리즘 무수정.** 스테이지별로 바뀌는 것은 시드·팔레트뿐.
6. **git commit 금지 · 파괴적 삭제 전 `docs/v1-archive/` 보존.**
7. **기본 공격은 검(`BASIC` 카드).** 빈 칸 = 기본 베기, 태그 없음.

## 1. 한 문장 컨셉 (갱신)

> **다섯 관문의 파수꾼을 넘어 마왕에 닿는 실시간 액션 로그라이크.
> 5칸 딜싸이클에 꽂은 원소의 *순서*가 곧 콤보이고, 기한은 없지만 머무는 밤마다
> 세계가 강해진다.**

v2와의 차이 세 줄:

| | v2 | v3 |
|---|---|---|
| 압박 | **7일 하드 기한**(819초) | **체류 압박** — 낮/밤 무한 반복, 주기마다 세계가 강해지고 **보상 효율은 떨어진다** |
| 구조 | 단일 필드 → 마왕성 | **5스테이지**(필드 + 성 + 베이스캠프 + 보스방) → 5번째 보스 격파 즉시 마왕전 |
| 전투 레이어 | 태그(공명·결속·삼각·반응) = **덱 레벨** | 위에 **원소 상태이상 매트릭스 = 대상 레벨**을 얹어 2층 구조 |

## 2. 스테이지 루프

### 2.1 한 스테이지의 구조

```text
[스테이지 N 개시]
  플레이어 스폰 (0,0) — 무적 1.2초, 스테이지 배너
  │
  ├─ 성(Castle)      스폰에서 약 350px. 고정 랜드마크. NPC 4종. 나침반 2번 줄
  │      · 출발 정비: 초기 자금으로 카드/각인 1~2개
  │
  ├─ 무한 필드 (WFC) — 낮/밤이 끝없이 반복
  │      · 레벨업 3지선다(카드 A / 카드 B / 각인 드래프트) — v2 무변경
  │      · 보물상자 · 균열 2회(dwell 1·3에 개설) · 밤의 전조(dwell≥2 매 밤)
  │      · **잠식(구 월식)** — dwell ≥ 임계에서 발동, 스테이지 클리어 시 해제
  │      · 매 주기 종료 시 dwell +1 → 몹 강화 · 보상 효율 하락
  │
  ├─ 베이스 캠프(Base Camp)  보스문에서 약 520px. 고정 랜드마크. 나침반 1번 줄
  │      · **성과 완전히 동일한 NPC 4종** (사용자 요구)
  │      · 스테이지당 1회 완전 회복(여관 역할)
  │
  └─ 보스방(Boss Gate)  스폰에서 3,600~4,200px, 방향은 스테이지 시드로 결정
         · 필드 위 원형 아레나(균열 렌더러 재사용, 반경 ×2.2) + 문 랜드마크
         · `E` → 보스 프리뷰(내 5칸 vs 보스 3칸, **취소 가능**) → 보스전
         · 격파 → 트로피 카드 2택1 → 완전 회복 → [스테이지 N+1 개시]
         · 5스테이지 보스 격파 → **필드 복귀 없이 즉시 마왕전**
```

### 2.2 스테이지 전환 구현 형태

**결정: 월드를 통째로 재생성한다.** `game.gd:4347`이 런 시작마다 이미
`WORLD_GRID_SCRIPT.new()`를 하고 있으므로, 그 블록을 `_begin_stage(n)`으로 추출하고
런 시작은 `_begin_stage(1)`이 된다.

검토하고 버린 대안 2개:

| 대안 | 버린 이유 |
|---|---|
| 하나의 월드에 스테이지별 좌표 영역 배정 | 좌표가 커질수록 WFC 해시 품질과 부동소수 정밀도가 흔들리고, 이전 스테이지로 걸어 돌아갈 수 있어 "관문" 은유가 깨진다 |
| WFC 시드만 갈고 청크 캐시 clear | `wfc_chunk_generator`의 `dry_zones` 배열이 지우는 API 없이 누적된다(`_part_allowed()`가 O(n) 순회). `world_grid`의 `rifts`·`opened_features`도 스테이지 잔재가 남는다. 재생성이 더 싸고 안전하다 |

**스테이지를 넘어 유지되는 것**: 플레이어 레벨/경험치/스탯, 5칸 덱과 각인, 보관함,
장비 4부위, 골드, `rejected_skills`(마왕 성장), `run_cycle_seed`, 총 일수, 트로피 효과.
**초기화되는 것**: 월드, 랜드마크, 균열 예산, `opened_features`, 잠식, dwell(부분 감쇠 §6.3).

### 2.3 랜드마크 배치 규칙

| 랜드마크 | 위치 | 나침반 | 비고 |
|---|---|---|---|
| 성 | `_stage_rng`로 스폰 반경 300~420px, 걸을 수 있는 칸 | 2번 줄 | v2 `STARTER_CASTLE_POSITION` 자리를 스테이지 시드로 대체 |
| 보스문 | 스폰 기준 각도 `stage_angle`, 거리 3,600~4,200px | **1번 줄(상시)** | v2 `DEMON_CASTLE_POSITION` 고정 좌표 폐기 |
| 베이스 캠프 | 보스문에서 플레이어 쪽으로 520px | 1번 줄에 병기(`캠프 · 보스문`) | 반드시 보스문보다 먼저 만나게 배치 |
| 균열 | v2 규칙 그대로(900~1,400px 링) | 3번 줄 | 스테이지당 예산 2 |

**랜덤 성(9%)은 삭제한다.** `world_grid._feature_for_chunk()`의 `roll < 9` 분기를 제거하고
그 9%를 상자에 넘긴다(`roll < 49` → `roll < 58`). 근거: 사용자가 "성 1개"라고 명시했고,
고정 성 + 고정 캠프 2지점 구조가 "출발 정비 → 파밍 → 최종 정비 → 진입"이라는
스테이지 서사를 만든다. **되돌리려면 상수 한 줄이다**(`CASTLE_FEATURE_ROLL`).

### 2.4 균열 · 전조 · 잠식(구 월식)의 거취 — **셋 다 유지, 전부 dwell로 재키잉**

| 시스템 | v2 트리거 | v3 트리거 | 근거 |
|---|---|---|---|
| 균열 | 2·4·6일차 낮 · 런당 3 | **dwell 1·3 · 스테이지당 2**(런 최대 10) | 각인·골드·완전회복 = 파밍 루프에 정확히 필요한 보상. 코드·저장·테스트가 전부 완성돼 있어 폐기가 오히려 손해 |
| 전조 | 3일차 밤~ · 매 밤 1기 | **dwell ≥ 2 · 매 밤 1기 · 전 스테이지** | 5스테이지면 마왕에게 넘기는 카드가 v2의 4~5배다. 마왕 각인을 **뜯을 기회**가 그만큼 늘어나야 마왕전이 성립한다. 전조는 v3에서 더 중요해졌다 |
| 월식 → **잠식(蠶食)** | 5일차~ 런 끝까지 | **dwell ≥ `max(2, 5 − stage)` · 스테이지 클리어 시 해제** | 연속 배율만으로는 "오래 머물면 나빠진다"가 눈에 안 보인다. 이름 붙은 임계선이 하나 있어야 체류 압박이 **읽힌다**. 필드가 붉게 물들고 모든 몹이 마왕 잔재를 든다 = 최고의 피드백 |
| 계약자 NPC | 하루 매매(+90G / 기한 −1일) | **체류 압박 매매**(§6.5) | 기한이 사라져 원래 기능은 무의미. 그러나 "압박을 화폐로 거래한다"는 발상은 v3의 새 축과 더 잘 맞는다. UI·저장(`pact_uses`)·테스트 전부 재사용 |

### 2.5 총 일수와 승리 등급

`clock.day_number`는 **기록 전용 카운터**가 된다(상한 없음). 승리 등급은 총 일수로 매긴다.

| 등급 | 조건(착수 초기값) |
|---|---|
| S | 총 13일 이하 |
| A | 총 17일 이하 |
| B | 총 23일 이하 |
| C | 24일 이상, 또는 **강림 안전 밸브**(§6.6)를 한 번이라도 밟음 |

기대 플레이 = 스테이지당 3~4일 × 5 = 15~20일. 확정은 `balance_probe` 확장판.

## 3. 보스 3종

### 3.1 로테이션과 에셋 선정

`art/external/ninja-adventure/Actor/Boss/` 20종을 **실측**해 고른 결과다(프레임 수는
`sips`로 확인한 실제 픽셀 크기 ÷ 프레임 한 변).

| 스테이지 | 보스 | 소스 디렉터리 | 원본 규격 | 보유 애니메이션 |
|---|---|---|---|---|
| 1 | **A · 서릿발 외눈** | `DemonCyclop2` | 50×50 | Idle 5f · Walk 6f · Hit 3f (**Attack 없음**) |
| 2 | **B · 역병 점액왕** | `GiantSlime2` (녹색·붉은 눈) | 62×52 | Idle 5f · Hit 5f · Jump 13f (**Walk/Attack 없음**) |
| 3 | **C · 홍염 천구** | `TenguRed` | 82×82 | Idle 6f · Walk 10f · Attack 15f · Hit 8f · **Trans 11f** |
| 4 | **B+ · 흑점액 변종** | `GiantSlime` (청색) + 자주 `_apply_tint` | 62×52 | 동일 |
| 5 | **C+ · 흑천구** | `TenguRed` + 암색 틴트 · **Trans를 등장 연출로 사용** | 82×82 | 동일 |
| 종료 | **마왕** | `GiantRedSamurai` (**무변경**) | 48×48 | v2 그대로 |

**선정 논리 — 등장 횟수에 리그 풍부도를 맞췄다.** 로테이션 [A,B,C,B+,C+]에서
A는 1회, B·C는 각 2회 등장한다. 그래서 A에 가장 얇은 리그(Attack 없음)를 배치하고
C에 가장 풍부한 리그(Attack 15f + Trans 11f)를 배치했다. 사용자가 지정한
"5스테이지 = 3번째 디자인 최강형"이 곧 C+이고, `TenguRed/Trans.png`가
**소형→대형 변신 11프레임**이라 C+의 등장 연출로 그대로 쓸 수 있다(실측 확인).

버린 후보와 이유:

| 후보 | 버린 이유 |
|---|---|
| `GiantBlueSamurai` | 마왕(`GiantRedSamurai`)과 픽셀 단위로 동일 리그라 파이프라인은 공짜지만, **마왕과 실루엣이 같아 최종 보스의 유일성이 깨진다** |
| `DragonBlue/Green` | 스프라이트시트가 아니라 파츠 조립형(Head/Body/Wing 개별 PNG). 현재 파이프라인 밖 |
| `GiantFlam` `GiantSpirit` | Idle 5f + Hit 3f뿐. 보스로 쓰기엔 너무 얇다 |
| `SquidRed` `GiantBamboo` | 리그는 충분하나 규격이 비정사각(76×79)이거나 62px라 셀 계산이 늘어난다. **예비 후보로 남긴다** — A가 플레이테스트에서 시각적으로 밋밋하면 `GiantBamboo`(Idle 6/Walk 12/Attack 5/Hit 4/Charge 3, 62px 균일)로 교체 |

**A의 Attack 애니메이션 부재는 설계로 흡수한다.** A의 공격은 팔을 휘두르는 동작이 아니라
**발구름 → 바닥 링 확산**이다. 텔레그래프 = 바닥 원형 VFX + 보스 스케일 펄스(`delta` 감쇠).
사지 애니메이션이 필요 없다. 리그 제약에 맞춰 패턴을 설계한 것이지 타협이 아니다.

### 3.2 보스의 딜싸이클 — **3칸(강화형 4칸), 각인·과열 없음, RELOAD 유지**

가장 중요한 판단이다. 근거:

- **마왕의 유일성 보존**: "마왕은 플레이어와 완전히 같은 런타임을 쓴다(5칸·각인·과열)"가
  v2의 핵심 서사다. 스테이지 보스까지 5칸+각인이면 마왕은 그냥 여섯 번째 보스가 된다.
  **5칸 + 각인 + 과열은 마왕만 가진다.**
- **문법의 일관성**: 그러나 RELOAD(반격 창)는 전 보스가 공유해야 한다. 플레이어는
  1스테이지 보스에서 "과열 오르면 피하고 RELOAD에 때린다"를 배우고 마왕에서 졸업한다.
- **구현 비용 0에 가깝다**: `DealCycleController(is_boss=true, uses_reload=true)`와
  마왕 레일 밴드 HUD를 **그대로** 쓴다. 칸 수만 3이면 된다
  (`FactoryDeck.ensure_slot_count()`가 이미 있다). `RuneEngine.triangle_ok()`는
  `deck.size() < 5`면 `false`를 반환하므로 3칸에서도 안전하다.
- **강화형(+)의 승급이 시각적으로 명확하다**: 3칸 → **4칸**. 레일에 칸이 하나 더 생긴다.

| 축 | 기본(A·B·C) | 강화(B+·C+) | 마왕 |
|---|---|---|---|
| 칸 수 | **3** | **4** | 5 |
| 각인 | 없음 | 없음 | 있음 |
| 과열 | 없음 | 없음 | 있음 |
| RELOAD 배율 | 0.75 | **0.55**(반격 창 축소) | 0.60 |
| 부여 상태이상 | 1종 | **2종 동시**(보스가 시너지를 쓴다) | 각인 의존 |
| 페이즈 전환 | HP 50% 1회 | HP 66% / 33% **2회** | 체력 구간 3회 소환 |

**보스 패턴은 플레이어 카드를 재사용하지 않는다.** 신규 `scripts/boss_library.gd`에
카드와 **같은 스키마**의 패턴 딕셔너리를 둔다(그래야 기존 런타임이 그대로 먹는다).
추가 키 2개: `status`(부여할 상태이상 id), `telegraph`(선딜, 초).

### 3.3 보스 3종 패턴 설계

**A · 서릿발 외눈 (빙 + 뇌) — "얼리고 감전시킨다" · 1스테이지**

| 칸 | 패턴 | 원소 | 형태 | telegraph | 효과 |
|---|---|---|---|---|---|
| 1 | 서리 발구름 | ice | wave | 0.55s | 반경 260 링. `chill` 부여 |
| 2 | 빙주 낙하 | ice | trap | 0.80s | 예고 원 3개 → 낙하. `chill` 강화 |
| 3 | 뇌격 방출 | thunder | pierce | 0.45s | 직선. **플레이어가 `chill` 상태면 피해 ×1.6** |

교육 목표: "보스도 시너지를 쓴다 / RELOAD가 반격 창이다". 가장 느리고 읽기 쉽다.

**B · 역병 점액왕 (독) — "분열하고 오염시킨다" · 2·4스테이지**

| 칸 | 패턴 | 원소 | 형태 | telegraph | 효과 |
|---|---|---|---|---|---|

### 3.4 강화형(B+ / C+) 규칙 — 데이터 한 벌로 파생

```text
enhanced(design) =
  칸 3 → 4 (해당 보스의 4번 패턴을 켠다)
  RELOAD 배율 0.75 → 0.55
  telegraph 전부 × 0.85
  부여 상태이상 1종 → 2종 (기본 원소 + 보조 원소)
  페이즈 1회 → 2회
  스프라이트: 색 변종 또는 틴트 (B+ = GiantSlime + 자주 / C+ = TenguRed 암색 + Trans 등장)
```

보스 HP: `hp = BOSS_DESIGN_HP[design] × stage_mul(stage) × (1 + 0.08 × dwell)`
dwell 항이 몹(§6.2)보다 완만한 이유: 오래 머문 플레이어를 **두 번 벌하지 않기 위해서**다.
몹이 이미 배로 강해졌는데 보스까지 같은 곡선이면 체류 압박이 아니라 체류 금지가 된다.

### 3.5 보스방 구조 — **전용 아레나(성 내부 재사용 아님)**

**결정: 필드 위 원형 아레나.** 근거는 코드다 — `_begin_boss_battle()`(`game.gd:8164`)은
이미 **필드 위 제자리에서** 싸운다. 적을 전부 `queue_free()`하고, 보스를 플레이어
옆(`_find_visible_boss_position`)에 스폰하고, 시간만 멈춘다. 별도 씬이 없다.

그래서 보스방은 이렇게 만든다:

- 균열 아레나 렌더러(`world_grid._draw_rift` · `T_CAMP` 바닥 덮개 · `rift_at()` 판정)를
  **반경 ×2.2로 복제**해 `boss_gate` 랜드마크를 만든다. 신규 씬 0개.
- 아레나 입구에 문 스프라이트(`TilesetTowers.png`/`TilesetDungeon.png`) 랜드마크.
- `E` → 기존 `boss_preview` 상태(취소 가능, 내 5칸 vs 보스 3칸 대조) → `boss` 상태.
- 새 `state` 문자열을 만들지 않는다. `current_interactable`에 `boss_gate` 타입만 추가.

버린 대안: `castle_interior.gd`처럼 별도 실내 노드. 보스전 런타임 전체가 필드 좌표계와
`combat_resolver`에 묶여 있어 실내로 옮기면 `_set_field_suspended` 경로와 충돌한다.
이득 없는 위험이다.

### 3.6 베이스 캠프 구성 — **성과 완전히 동일한 4종**

사용자 요구 원문("성이랑 똑같아")을 그대로 따른다.

- `castle_interior.setup(services, feature_id, variant)` — **3번째 인자만 추가.**
  `variant`가 바꾸는 것: 바닥 텍스처, 벽 색, 옥좌 유무, 입장 배너 문구. 그게 전부다.
- 서비스는 `CASTLE_SERVICES_V2` 4종 그대로(카드 상점 · 각인 세공사 · 계약자 · 밀정).
  NPC 좌표 배열 4개도 그대로 맞는다.
- **추가 1건**: 베이스 캠프는 **스테이지당 1회 완전 회복**을 준다(여관 역할).
  저장 키 `camp_rest_used` 1개. 근거 — 캠프를 안 쓰고 낮은 체력으로 보스방에 들어가는
  것이 최적이 되면 "정비하고 들어간다"는 요구가 무너진다.
- 파라미터화가 필요한 하드코딩(조사 결과): `ROOM_BOUNDS` / `EXIT_POSITION` /
  `get_spawn_position()` / `_draw()`의 `range(-460,461,40)`가 **서로 독립 리터럴 4곳**이다.
  전부 `ROOM_BOUNDS`에서 파생시키는 것을 V5의 완료 기준에 넣는다.

## 4. 원소 상태이상 시너지 (신규 전투 레이어)

### 4.1 2층 구조 — 이게 설계의 뼈대다

v2에는 이미 **덱 레벨 원소 반응**이 있다(`rune_engine.REACTIONS` 3쌍:
`ice>thunder` 감전 / `fire>ice` 증기 / `fire>thunder` 과충전). v3는 이걸 **버리지 않고
아래층으로 삼는다.**

| 층 | 어디서 판정 | 무엇을 본다 | 결정적인가 | 미리보기 가능 | 무엇을 준다 |
|---|---|---|---|---|---|
| **L1 덱 레벨** | `RuneEngine.simulate_cycle()` | **직전에 실행한 칸의 원소** | 예 | **예**(편집 화면 96표본) | 범위·과열·RELOAD·**상태 위력(potency) 배율** |
| **L2 대상 레벨** | `StatusEngine` (신규) | **적 개체에 붙어 있는 상태** | 아니오(전장 상황) | 아니오 | **모든 상태 피해**(도트·폭발·전이) |

**중요한 분리 규칙**: L1은 **직접 피해를 주지 않는다**. L2는 **사이클 피해 배율을 곱하지
않는다**. 그래서 `_cycle_damage_value()`가 "사이클 타격 피해의 유일한 계산 지점"이라는
v2 계약이 깨지지 않고, 상태 피해는 `StatusEngine`이라는 **두 번째 단일 지점**을 갖는다.
이중 계산이 구조적으로 불가능하다.

### 4.2 원소 7계 (v2의 6계에서 재편)

| v3 | 한글 | v2에서 온 곳 | 역할 |
|---|---|---|---|
| `poison` | 독(毒) | `blood` 혈 | 축적 → 터뜨리는 도트 |
| `ice` | 빙(氷) | `ice` 그대로 | 감속 · 전도의 매개 |
| `thunder` | 뇌(雷) | `thunder` 그대로 | 전이 · 광역화 |
| `fire` | 화(火) | `fire` 그대로 | 짧고 굵은 도트 · 모든 폭발의 점화원 |
| `oil` | 유(油) | **신규** | 피해 0. 화염 증폭기 |
| `strike` | 타(打) | `iron` 철 | 비원소. 상태를 **터뜨린다** |
| `psi` | 초(超) | `light` 광 | 비원소. 상태를 **환금한다** |

**`blood→poison` / `light→psi` / `iron→strike`는 개명이 아니라 역할 승계다.** 기존
20+8장의 태그를 처음부터 다시 붙일 필요가 없다(§5). 이게 이번 개편에서 구현 규모를
가장 크게 줄인 판단이다.

### 4.3 상태이상 5종 — 데이터 모델

적 1기가 가지는 상태는 **고정 크기 float 묶음**이다. 딕셔너리·오브젝트를 쓰지 않는다.
`enemy.gd:319 apply_cycle_slow()` / `enemy.gd:78~80`의 기존
`cycle_slow_timer`/`cycle_slow_multiplier` 패턴을 그대로 복제한다.

| 상태 | 한글 | 지속 | 중첩 | 틱 | 효과 (P = 적용 시점의 `_cycle_damage_value` × POTENCY) |
|---|---|---|---|---|---|
| `poison` | 독 | 6.0s | **1~6** | 0.25s | `0.045 × P × stacks` 피해. **1.5초마다 스택 −1**(서서히 감소) |
| `burn` | 연 | **2.0s** | 없음 | 0.25s | `0.10 × P` 피해. **금방 꺼진다** |
| `chill` | 한 | 3.5s | 없음 | — | 이동 `×(1 − 0.35 × power)`. 전도의 매개 |
| `oil` | 유 | **8.0s** | 없음 | — | **자체 피해 0.** 받는 화염 피해 ×2.2 |
| `shock` | 전 | 0.8s | 없음 | — | 다음 피격 +12%. 표식 |

지속시간 합계 검산: 독 6초 = 24틱 × 평균 3스택 × 0.045 = **약 3.2 P**(스택 감소 반영 시 ≈2 P).
연 2초 = 8틱 × 0.10 = **0.8 P**. 기름 위의 연 = power ×3, 지속 ×2.5(5초) = **6.0 P**.
즉 **기름+불이 맨 불의 7.5배**다 — 사용자가 말한 "대폭 연소"가 숫자로 성립한다.

### 4.4 시너지 매트릭스 (정식)

**행 = 지금 적용하는 원소 / 열 = 대상에 이미 붙어 있는 상태.** 빈 칸 = 상호작용 없음(각자 유지).

| ↓적용 \ 기존→ | (없음) | `poison` 독 | `burn` 연 | `chill` 한 | `oil` 유 | `shock` 전 |
|---|---|---|---|---|---|---|
| **`poison` 독** | 독 부여 | **스택 +1** | — | 독 지속 **+50%** (냉기가 독을 가둔다) | — | — |
| **`fire` 화** | 연 부여 | **역병 발화** — 스택 전부 소모, 반경 90에 `1.2 × P × stacks` 즉발 | 연 갱신 | **증기** — 한 해제, 이번 타격 범위 **+50%** *(v2 `fire>ice` 계승)* | **★대폭 연소** — 기름 소모, 연 power ×3 · 지속 ×2.5 · 반경 130 내 적에게 `oil` 전파(**깊이 1**) | — |
| **`ice` 빙** | 한 부여 | 독 지속 +50% | 연 **해제** 후 한 부여 | 한 갱신·강화 | — | — |
| **`thunder` 뇌** | 전 표식 | — | — | **★전도(傳導)** — 반경 260 내 **`chill` 상태 적**에게 전이. 대상마다 `0.55 × P` + 전 표식. **최대 4체, 도약당 −20%** *(v2 `ice>thunder` 계승)* | **감전 유막** — 기름 소모, 반경 160에 `0.8 × P` + 전 표식 | 전 갱신 |
| **`oil` 유** | 유 부여 | — | 연 power **×2**(불에 기름) | — | 유 갱신 | — |
| **`strike` 타** | (상태 없음) | **터뜨리기** — 스택 1 소모, `1.0 × P` 즉발 | — | **쇄빙** — 한 해제, 넉백 ×2 · 경직 0.35s | — | — |
| **`psi` 초** | (상태 없음) | ← **정신 붕괴** — 대상의 **모든 상태의 남은 지속을 30% 즉시 소모**하고, 소모한 총 초 × `0.5 × P`를 단일 대상 즉발 → | | | | |

★ = 사용자가 명시적으로 요구한 두 조합.

**설계 의도 3가지**

1. **비원소 2종은 생산자가 아니라 소비자다.** `strike`·`psi`는 상태를 만들지 않고
   **거둬들인다.** 그래서 5칸 배치에서 자연히 **뒤쪽 마무리 칸**에 놓이게 되고,
   그것이 곧 "순서가 콤보"라는 요구의 기계적 실체다.
2. **`oil`은 피해가 0이다.** 단독으로는 완전히 무의미하고 오직 `fire`와만 의미가 있다.
   가장 극단적인 순서 의존 원소를 하나 두어 조합의 하한을 만든다.
3. **`chill`은 두 얼굴이다.** `thunder`에겐 전도의 매개, `fire`에겐 증기(범위),
   `strike`에겐 쇄빙(경직). 같은 상태가 셋 다른 결과를 내므로 "무엇을 다음에 꽂을까"가
   매 사이클 질문이 된다.

### 4.5 L1(덱 레벨) 반응 확장

`rune_engine.REACTIONS`를 3쌍 → **7쌍**으로 늘린다. **직접 피해는 주지 않는다.**

| 반응 키 | 이름 | 효과 | v2 |
|---|---|---|---|
| `fire>thunder` | 과충전 | 과열 +1 (무상) | 기존 유지 |
| `fire>ice` | 증기 | 범위 +50% | 기존 유지 |
| `ice>thunder` | 감전 | 광역 추가타 +35% | 기존 유지 |
| **`oil>fire`** | **인화** | 이 칸의 **상태 위력(potency) ×1.5** | 신규 |
| **`poison>fire`** | **역병 발화 준비** | 이 칸의 상태 위력 ×1.3 | 신규 |
| **`chill>strike`** | **쇄빙 준비** | 경직 +0.2s | 신규 |
| **`*>psi`**(직전 칸 원소 무관·비어있지 않으면) | **공명 흡수** | RELOAD −0.15초 | 신규 |

`potency`는 신규 채널이다. `simulate_cycle()`의 `step_record`에 `potency` 키를 추가하고
`combat_resolver`가 상태 부여 시 곱한다. **편집 화면 96표본 미리보기가 그대로 보여준다.**

### 4.6 딜싸이클과의 결합 — 실증 빌드 3종

v2의 태그 규칙(공명·결속·삼각)과 v3의 상태 매트릭스가 **같은 배치를 동시에 보상**하는지
확인한 것이다. 이게 성립하지 않으면 두 시스템은 서로를 방해한다.

**① 유화 폭연 (사용자가 지목한 "기름칸→회귀→불칸 반복")**

```
[1 기름 늪 유·설치] [2 업화의 장막 화·설치] [3 역청 폭우 유·설치] [4 운석검 화·설치] [5 용암 균열 화·관통]
 └ 2칸에 「되감기1」 각인 → 화(2) 실행 후 확률로 유(1)로 되감김 → 다시 화(2)
 L1: 유>화 인화 ×2회 → potency ×1.5
 L2: oil→fire 대폭 연소 사이클당 2회 (각 6.0 P)
 태그: 1·3·5 = 설치·설치·관통 → 삼각 ✗ / 결속 ✗ (교차 배치라 당연)
 성격: 폭발적, RELOAD가 길다. 과열로 밀어붙이는 빌드.
```

**② 빙뇌 전도 (밤 물량 특화)**

```
[1 빙결 파문 빙·파동] [2 빙정 결계 빙·수호] [3 뇌전 심판 뇌·파동] [4 섬전 순참 뇌·참격] [5 뇌창 유도 뇌·관통]
 태그: 3·4·5 뇌 연속 → **결속** (그 구간 각인 과열 비용 ×0.5)
 L1: ice>thunder 감전(광역 +35%)
 L2: 1·2칸이 무리 전체에 chill → 3칸 뇌가 전도로 4체 전이(0.55 P씩)
 성격: 개체 피해는 낮고 광역이 압도적. 잠식 발동 후 밤에 강하다.
```

**③ 독 축적 폭발 (v2 태그 규칙과 완전 정합)**

```
[1 맹독 십자참 독·참격] [2 혈풍 회전참 독·파동] [3 피의 서약 독·참격] [4 업화의 장막 화·설치] [5 혈월 처형 독·참격]
 태그: 1·2·3 독 연속 → **결속** / 1·3·5 참격 → **삼각**(RELOAD −12%) / 1-2, 2-3 인접 → **공명 ×2**
 L1: poison>fire 역병 발화 준비 (potency ×1.3)
 L2: 1~3칸이 독 스택 3~5 축적 → 4칸 화가 **역병 발화**(1.2 P × stacks 광역) → 5칸이 마무리
 성격: v2 규칙 3종을 한꺼번에 켜면서 v3 매트릭스의 최대 폭발을 낸다. **두 시스템이

```

## 5. 스킬 풀 재설계

### 5.1 규모 판단 — **드래프트 28종 (7원소 × 4장)**

| 기준 | 결론 |
|---|---|
| 결속(같은 원소 3칸 연속)이 7원소 전부에서 가능해야 한다 | 원소당 **≥3장** → 최소 21 |
| 삼각(1·3·5 같은 형태)이 5형태 전부에서 가능해야 한다 | 형태당 **≥3장** |
| 근접 + 원거리 혼합 단일 풀 | **원소마다 근접(`range` < 200) ≥1 · 원거리(≥260) ≥1** |
| 아이콘 아틀라스 7×4 = **28칸** | **정확히 28** |

→ **28종. 7원소 × 4장. 신규 id 0개.**

### 5.2 신규 id를 만들지 않는다 — 이번 개편 최대의 비용 절감

v2에는 드래프트 20 + legacy 8 = **28장의 카드 데이터와 28개의 아이콘 인덱스**가 이미 있다.
legacy 8장은 `draft_pool()`에서만 빠져 있을 뿐 `by_id()`·아이콘·VFX 분기가 전부 살아 있다.

**legacy 8장을 전부 드래프트 풀로 승격한다 → 정확히 28장.** 그리고 태그만 재배치한다.

동기화해야 하는 지점이 **id 하나당 10곳**이다(`skill_icon.GENERATED_SKILL_INDEX`,
`cycle_skill_effect._draw_signature` match, `player._apply_skill_stats` match,
`palette.gd` match, `patch_library`, `debt_module()`, `data_test:448`, `test_runner` 다수,
아틀라스 PNG 자체). **id를 하나도 안 바꾸면 이 10곳이 전부 무변경이다.**

### 5.3 28장 태그 재배치 (id 고정)

| 원소 | 4장 (기존 id) | v2 태그에서 온 곳 |
|---|---|---|
| **화** fire | `flame_field` · `meteor_blade` · `earth_splitter` · `lion_roar` | fire 3 + legacy fire 1 |
| **빙** ice | `dash_blade` · `frost_ring` · `guardian_blade` · `moon_barrier` | ice 3 + **light→ice 1** |
| **뇌** thunder | `thunder` · `time_cut` · `targeting` · `phantom_step` | thunder 3 + legacy thunder 1 |
| **독** poison | `whirlwind` · `blood_pact` · `execution` · `cross_cut` | blood 3 + **iron→poison 1** |
| **유** oil | `gravity_well` · `sword_rain` · `aura` · `boomerang_blade` | **ice→oil 1** + legacy 3 |
| **타** strike | `cleave` · `rapid_slash` · `thrust` · `recursion` | iron 4 |
| **초** psi | `shield_bash` · `holy_pulse` · `battle_trance` · `blade_fan` | light 3 + legacy light 1 |

**`oil` 4장이 전부 설치·파동·투척인 것은 의도다.** 기름은 바닥에 칠하는 원소여야
"먼저 칠하고 나중에 태운다"는 순서가 자연스러워진다.

**형태(form) 5종은 유지**하되 재배치해 형태당 ≥5장을 맞춘다. `data_test`에 신규 단언 2개:
원소당 정확히 4장 / 원소당 근접·원거리 각 ≥1장.

### 5.4 전면 판타지 명명 — **진짜 풍자는 아이템에 있다**

사용자가 말한 "직장 풍자 잔재 ~30종"의 실체를 확인했다.

- **스킬 카드 표시명은 이미 W7이 판타지로 통일했다**(`deal_card_library.gd:25` 주석).
  남은 풍자는 **id에만** 있고(`recursion`·`targeting`·`aegis_process`·`pain_compiler`…),
  id는 위 §5.2 이유로 **절대 바꾸지 않는다**(사용자에게도 안 보인다).
- **실제 풍자 표시명은 `item_library.gd` 57종에 있다.** 실측: `무거운 야근검` `회의종결 대검`
  `잔업용 쌍칼 한쪽` `납기 반지` `경험 많은 척 반지` `대시 출석 팔찌` `주말 반납 대검`

→ **명명 작업의 실제 대상은 ①아이템 57종 전량(특히 풍자 30종) ②스킬 28종의 v3 원소
재배치에 맞춘 개명 ③트로피 카드 12종의 계보 색 제거.** `name` 키만 바꾸고 `id`는 금지.

이름 교체 시 조용히 깨지는 곳 3군데(조사 결과):
`class_library.gd:39/50/61`의 `tier1_desc` 산문에 카드명이 박혀 있고(→ §5.5로 폐기),
`"기본 베기"` 리터럴이 8곳에 하드코딩돼 있으며, `game.gd:6786`이 상점 오퍼에 **이름을
복사 저장**한다(세이브에 구 이름이 남는다).

### 5.5 계보 · 각성 · SPECIALS 12종의 거취

**계보 3종과 각성 2단계는 폐기한다**(사용자 요구). 그러나 **SPECIALS 12종은 살린다.**

| 대상 | 판정 | 형태 |
|---|---|---|
| `ClassLibrary.BRANCHES` 3계보 | **폐기** | |

`player.gd:348~352`가 존재하지 않는 키(`tier1_skill`/`tier2_skill`)를 읽고 있는
**끊어진 참조 1건**도 이때 정리한다.

## 6. 체류 압박 곡선

### 6.1 dwell의 정의

```
dwell = 현재 스테이지에서 완료한 낮/밤 전체 주기 수 (0부터)
```

스테이지 개시 시 0이 아니라 **부분 감쇠된 값**에서 시작한다(§6.3).
`clock.day_number`(총 일수)는 기록 전용이고, **모든 난이도는 dwell이 만든다.**

### 6.2 곡선 — 초반 관대, 후반 무한

| 축 | 식 | 설계 의도 |
|---|---|---|
| 몹 HP | `H(d) = 1 + 0.14d + 0.012d²` | 2차항이 "초반 관대 · 후반 무한"을 만든다 |
| 몹 피해 | `A(d) = 1 + 0.07d + 0.004d²` | HP의 절반 기울기 |
| 몹 속도 | `min(1.30, 1 + 0.012d)` | **상한 필수.** 속도가 무한이면 회피가 불가능해진다 |
| 물량 | `base + 3 × min(d, 6)` | **d=6에서 포화.** 그 뒤로는 수가 아니라 질만 는다 |
| 정예 비율 | `min(0.35, 0.03d)` | 개체 수를 안 늘리고 난도를 올리는 유일한 축 |
| **XP 보상** | `H(d)^0.5` | ← **이 한 줄이 체류 압박의 실체다** |
| **골드 보상** | `H(d)^0.4` | |

| d | HP × | 피해 × | 속도 × | 물량 + | 정예% | XP × | **킬당 효율(XP/HP)** |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 1.00 | 1.00 | 1.00 | +0 | 0% | 1.00 | **1.00** |
| 1 | 1.15 | 1.07 | 1.01 | +3 | 3% | 1.07 | 0.93 |
| 2 | 1.33 | 1.16 | 1.02 | +6 | 6% | 1.15 | 0.87 |
| 3 | 1.53 | 1.25 | 1.04 | +9 | 9% | 1.24 | 0.81 |
| 4 | 1.75 | 1.34 | 1.05 | +12 | 12% | 1.32 | **0.76** |
| 6 | 2.27 | 1.56 | 1.07 | +18 | 18% | 1.51 | 0.66 |
| 8 | 2.89 | 1.82 | 1.10 | +18 | 24% | 1.70 | 0.59 |
| 10 | 3.60 | 2.10 | 1.12 | +18 | 30% | 1.90 | 0.53 |
| 12 | 4.41 | 2.42 | 1.14 | +18 | 35% | 2.10 | **0.48** |

**보상을 HP의 제곱근으로 준 것이 이 시스템의 전부다.** 이게 없으면 몹이 강해질수록
경험치도 늘어 순효율이 그대로고, "오래 머물수록 손해"가 **거짓말**이 된다.
d=12에서 킬당 효율이 절반이 된다 = 레벨업 속도가 절반이 된다 = 시간을 두 배 써야 한다.
이것이 사용자가 요구한 "자연스럽게 전진하게 되는" 압력의 유일한 기계적 근거다.

**v2 상수의 처리** — `NIGHT_ENEMY_LIMIT_BASE + 4×day` 계열은 **day를 소비하는 것을
금지**한다. 전부 `min(d, 6)` 기반 물량 식으로 교체한다. 그대로 두면 12일차에
`MAX_ENEMIES=78`을 돌파해 프레임이 죽는다.

### 6.3 스테이지 전환 시 dwell 처리 — 절반 감쇠

```
dwell_next = floor(dwell_cleared × 0.5)
```

| 대안 | 판정 |
|---|---|
| 완전 리셋(0) | **버림.** 플레이어 파워는 누적되는데 난이도만 리셋되면 5스테이지가 가장 쉬워진다 |
| 이월 없음(누적 계속) | **버림.** 스테이지마다 "초반 관대" 구간이 사라져 사용자 요구와 어긋난다 |
| **×0.5 감쇠** | **채택.** 보스 격파가 실질적 안식을 주되(rush한 사람은 0~1, 과파밍한 사람은 5~6에서 시작) 과파밍의 대가가 **다음 스테이지까지 따라온다** |

여기에 **스테이지 기저 배율**이 곱해진다(리셋되지 않는 축).

| 스테이지 | HP 기저 | 피해 기저 | 몹 풀 | 낮/밤 | 잠식 dwell 임계 | 보스 |
|---|---:|---:|---|---|---:|---|
| 1 | 1.00 | 1.00 | T1 4종 | 72 / 45 | 4 | A |
| 2 | 1.55 | 1.28 | T1+T2 6종 | 68 / 52 | 4 | B |
| 3 | 2.10 | 1.56 | T2+T3 8종 | 62 / 60 | 3 | C |
| 4 | 2.65 | 1.84 | T3 9종 | 56 / 68 | 3 | B+ |
| 5 | 3.20 | 2.12 | T3+T4 10종 | **48 / 78** | **2** | C+ |

최종 배율 = `stage_base × H(dwell)`. 5스테이지 dwell 4 → **HP ×5.61**.

### 6.4 마왕 성장의 재보정 (필수)

5스테이지면 마왕에게 넘어가는 카드가 v2의 4~5배다. **그대로 두면 마왕이 폭주한다.**

| 상수 | v2 | v3 초기값 | 근거 |
|---|---|---|---|
| `BOSS_CARDS_PER_RUNE` | 2 | **4** | 각인 획득 속도를 절반으로 |
| `BOSS_RUNE_CAP` | 12 | **16** | 5스테이지분의 상한 소폭 상향 |
| `BOSS_HP_PER_DEBT` | 70.0 | **22.0**, 그리고 `min(debts, 45)` | 60장 × 70 = 4,200. 기저 611을 압도한다 |
| `hp_multiplier` | `1 + 0.22×(day−1)` | `(1 + 0.05 × total_days) × (1 + 0.15 × stages_cleared)` | 20일에 ×5.18 → **×3.5** |
| `DESCENT_HP_MUL` | 1.15 | (강림 개념 이전, §6.6) | |

**전조로 각인을 뜯는 행동의 가치가 v3에서 크게 오른다.** 그래서 §2.4대로 전조를
전 스테이지에 배치했다. 확정은 `balance_probe` 확장판.

### 6.5 계약자 NPC — 체류 압박을 거래한다

| v2 서비스 | v3 서비스 | 저장 |
|---|---|---|
| 하루를 판다 (+90 G, 기한 −1일) | **정비(Respite)** — `dwell −1` (비용 `120 + 60 × 사용횟수` G) | `pact_uses` 그대로 |
| 하루를 산다 (−G, 기한 +1일) | **탐욕(Greed)** — `dwell +1`, 즉시 200 G + 각인 조각 1 | 동일 |
| 미래를 담보로 영웅 각인 | **유지 · 비용을 `dwell +2`로 변경** | 동일 |

거래당 2회 제한 유지. **압박을 골드로 되사는 것**이 v3에서 가장 자연스러운 경제 행위다.
UI·모달·저장·`--castle-test` 뼈대 전부 재사용.

### 6.6 강림 안전 밸브 — **사용자 확인 필요 항목 ①**

기한이 없으면 **끝내 진입하지 않는 플레이**가 이론상 가능하다. 안전 밸브를 제안한다.

```
dwell ≥ DWELL_DESCENT[stage]  (= [14, 13, 12, 11, 10])  →  스테이지 보스가 필드로 강림
  · 프리뷰 없음 · 칸 +1(즉 A도 4칸) · HP × 1.15
  · 이 경로를 한 번이라도 밟으면 승리 등급이 C로 고정
```

`_trigger_descent()` 경로를 **거의 그대로** 재사용한다. dwell 14 = 스테이지 하나에
약 28분이라 정상 플레이는 절대 닿지 않는다.

**이것이 "기한 삭제"에 어긋난다고 판단하시면 삭제 가능하다.** 삭제 시 대가는
"무한 정체 플레이가 가능해진다"는 것뿐이고, §6.2의 보상 감쇠가 이미 그것을
경제적으로 무의미하게 만든다.

## 9. 저장 (schema 3)

**`RUN_SCHEMA_VERSION`을 2 → 3으로 올린다. v2 세이브는 폐기된다.**

v2 규칙은 "가산 키는 버전을 올리지 않는다"이지만, v3는 **기존 키의 의미가 바뀐다**:
`cycle_number`/`day_number`(7 상한 소멸), `eclipse_active`(트리거 변경), `pact_uses`(기능 변경),
`player_advancement_branch`/`_tier`(계보 폐기). 마이그레이션 코드를 쓰는 것보다
폐기가 안전하고, 아직 플레이테스트 전이라 실사용 세이브가 없다.

`_read_run_snapshot()`의 `< RUN_SCHEMA_VERSION` 게이트가 조용히 버려 주므로 코드 변경은
상수 한 줄이다.

**신규 키 (기존 41 → 약 49)** — *구현 결과 **48키**다(V9 확정 49 − V10 삭제 1).*

| 키 | 내용 |
|---|---|
| `stage_index` | 1~5 |
| `stage_seed` | 스테이지 월드 시드(WFC·랜드마크·보스문 각도 전부 여기서 파생) |
| `stage_dwell` | 현재 dwell |
| ~~`stage_boss_defeated`~~ | ~~스테이지별 격파 기록 배열~~ — **넣지 않았다**(아래 주) |
| `stage_landmarks` | 성·캠프·보스문 좌표(재생성 대신 복원 — 결정성 보험) |
| `camp_rest_used` | 캠프 완전회복 소진 여부 |
| `blight_active` | 잠식(구 `eclipse_active`) |
| `total_days` | 기록용 총 일수 |
| `trophy_effects` | 보스 트로피 누적 효과 배열 |

> **설계-코드 불일치 1건 (V9 판정 · V10 확정 · 문서 쪽을 고쳤다).**
> `stage_boss_defeated`(배열)는 **구현하지 않았다.** V8이 트로피를 도입하면서 격파
> 4경로(`defeat` · `enhanced` · `demon_direct` · `valve`)가 **전부** 트로피를 지나가게
> 됐고, 그래서 `trophy_stages`가 이미 "보스를 깬 스테이지 번호 배열"이다. 같은 사실을
> 두 배열에 적으면 어긋날 자리만 생긴다.
> V9는 대신 격파 **수**를 `stage_bosses_defeated`로 저장했는데, **V10이 그것도 지웠다** —
> 읽는 코드가 한 줄도 없었고(write-only) 값이 `deadline_clock.stages_cleared`와 항상
> 같았다. 결과 화면의 "관문" 칩이 이미 그쪽을 쓴다.

**삭제 키**: `player_advancement_branch` · `player_advancement_tier` · `boss_advancement`
(→ `trophy_effects`로 대체).

**상태이상은 저장하지 않는다.** 전투 중 수 초짜리 휘발 상태다. 복원 시 전부 0.

`--save-test`는 v2와 같은 3단(키 존재 · 상태 지문 대조 · 좌표/예산 일치)을 유지하되
지문 축을 47 → 약 55로 늘리고 **스테이지 전이 왕복**(1→2 전이 후 저장·복원)을 추가한다.

## 부록 A. v3 확정 결정

> 이 섹션이 본문과 충돌하면 **이 섹션이 우선**한다. 구현 웨이브는 여기부터 읽는다.

### A-1. 사용자가 지시한 것 (원문 그대로 · 변경 금지)

1. **총 5스테이지.** 스테이지마다 무한 필드(WFC 유지) + 성 1개 + 보스방 1개.
   유저는 알아서 파밍하고 준비되면 보스방에 진입한다.
2. **"보스 방 전에 베이스 캠프 만들어줘. 성이랑 똑같아. 정비하고 들어갈 수 있게"**
3. **보스 3종 로테이션 [A, B, C, B강화, C강화].** 5스테이지 보스(3번째 디자인의 최강형)를
   처치하면 **필드 복귀 없이 즉시 마왕전**.
4. **7일 하드 기한 삭제.** 스테이지 내에서 낮/밤이 계속 반복되고 **주기마다 몹이 무한
   강화**된다. 오래 머물수록 손해라 자연스럽게 전진하게 만든다. **총 일수는 기록·등급용.**
5. **스테이지가 오를수록 그래픽을 더 어둡고 험악하게.**
6. **직업(계보·각성) 제거.** 근접+원거리 혼합 단일 스킬 풀. **기본 공격은 검 유지.**
7. **스킬명 전면 판타지화** (직장 풍자 잔재 약 30종 포함 전부).
8. **원소 상태이상 시너지** — 독(묻으면 도트 유지·서서히 감소 또는 중첩 후 터짐) /
   빙결(감속 → 감속 상태에서 전격 맞으면 주변 감속 적에게 전이 + 추가피해) /
   화염(주기 도트지만 금방 꺼짐) / 기름(자체 피해 낮고 불과 대폭 연소) /
   타격·초능력 등 비원소도 간간이. **"각 스킬별로 특성을 가져서 딜싸이클에서
   상호작용 되도록"** — 5칸 순서가 시너지 조합기가 되게 한다.
9. **불변**: 5칸 무스크롤 딜싸이클 · 바늘 · 과열 · 각인(칸 부착·중복 강화·칸 교환) /
   미선택 카드·각인 → 마왕 / 트윈 루프 애니메이션 금지 / WFC 무한 맵 재사용 /
   git commit 금지 / 파괴적 삭제 전 `docs/v1-archive/` 보존.

### A-2. 설계가 확정한 것 (오케스트레이터 승인 필요 없음)

10. **스테이지 전환 = 월드 통째 재생성.** `_begin_stage(n)` 추출, `_begin_run` = `_begin_stage(1)`.
11. **랜덤 성(9%) 삭제.** 스테이지당 고정 성 1 + 고정 베이스캠프 1. 되돌리기는 상수 한 줄.
12. **보스 딜싸이클은 3칸(강화형 4칸), 각인·과열 없음, RELOAD 유지.**
    **5칸 + 각인 + 과열은 마왕만 가진다.**
13. **보스방 = 필드 위 원형 아레나**(균열 렌더러 재사용). 신규 씬 0개, 신규 `state` 0개.
14. **베이스캠프 = `castle_interior.setup()`에 `variant` 인자 하나.** 서비스 4종 동일 +
    스테이지당 1회 완전회복.
15. **원소 7계**: `poison`(←blood) `ice` `thunder` `fire` `oil`(신규) `strike`(←iron) `psi`(←light).
16. **상태이상 5종**: `poison` `burn` `chill` `oil` `shock`. 매트릭스는 §4.4가 정본.
17. **2층 구조**: L1(덱, `RuneEngine`, 피해 없음, 미리보기 가능) / L2(대상, `StatusEngine`,
    모든 상태 피해). **L1은 피해를 주지 않고 L2는 사이클 배율을 곱하지 않는다.**
18. **스킬 드래프트 28종 = 7원소 × 4장. 신규 id 0개.** legacy 8장을 승격하고 태그만 재배치.
    아이콘 아틀라스 무변경.
19. **개명의 실제 대상은 아이템 57종**(풍자 30종이 여기 있다). 스킬 표시명은 W7이 이미
    판타지화했고 풍자는 id에만 남아 있으므로 **id는 건드리지 않는다.**
20. **SPECIALS 12종 = 보스 트로피 카드로 생존.** `advancement_choice` 상태와
    `_apply_class_effect()` 재사용. `class_library.gd` → `trophy_library.gd`.
21. **dwell 곡선** §6.2. **보상은 `H(d)^0.5`** — 이 한 줄이 체류 압박의 실체다.
22. **dwell 스테이지 전환 시 ×0.5 감쇠.**
23. **지형 아틀라스 3벌 사전 빌드 + 런타임 스테이지 그레이드.** 실측: 소스에
    잔디/모래/설원/자주 4팔레트 실재, **용암 팔레트는 없다.**
24. **낮/밤 길이가 스테이지별로 바뀐다** (72/45 → 48/78). 그래픽 가중치의 절반.
25. **저장 schema 3.** v2 세이브 폐기.
26. **`--deadline-test` → `--stage-test` 재작성 / `--status-test` 신설.** 총 14종.
