```
[낮 72초] 무한 필드 탐험 — 마물 사냥 / 균열 도전 / 성 방문 / 상자
    └ 레벨업 → 홀수: 스킬 2택1(미선택→마왕) / 짝수: 각인 3택1(미선택 2개→마왕 각인 재료)
    └ 언제든 ESC → 5칸 편집: 카드 순서를 바꿔 각인 흐름을 다시 조립
[밤 45초] 습격. 3일차부터 마왕의 전조 1기 등장(그의 한 칸을 시연)
    └ 전조 격파 → "각인 뜯기" 또는 "카드 회수" 2택1
[일 종료] 일수 +1. 마왕 프리뷰 갱신(그가 무엇을 받았는지 공개)
    ...
[3일차부터] 마왕성 개방 — 언제든 도전 가능. 빨리 갈수록 마왕이 약하고 나도 약하다
[7일차 밤 종료] 강림 — 마왕이 플레이어 위치로 내려온다. 프리뷰 없음, 보정 있음
```

**한 사이클(전투) 단위 루프**

```
바늘이 1칸 → 카드 실행 → 각인 굴림
    ├ 아무것도 안 터짐 → 2칸으로
    ├ 되감기 터짐 → 이전 칸으로 (과열 +1, 화력 +12%, RELOAD 빚 +)
    ├ 재실행 터짐 → 같은 칸 한 번 더 (재진입 감쇠 ×0.82)
    └ 도약 터짐 → 한 칸 건너뜀 (그 칸의 RELOAD를 안 냄 → 사이클 가속)
...
바늘이 5칸을 넘어감 → 사이클 완료 → RELOAD(누적 빚 × 과열 배율) → 과열 0 → 1칸으로
```

**"재미있는 딜싸이클을 조립하는 것 자체가 게임"** 이 되려면 플레이어의 의사결정이
①어떤 카드를 ②어느 칸에 ③어떤 각인과 함께 놓을 것인가 — 세 축이어야 한다. §3이 그 세 축을 정의한다.

## 3. 5칸 딜싸이클과 각인 시스템

### 3.1 용어

| 용어 | 영문 | 정의 |
|---|---|---|
| **칸** | slot | 1~5. 각각 카드 1장 + 각인 0~3개를 담는다 |
| **바늘** | playhead | 지금 실행 중인 칸을 가리키는 지시자. 기본은 1→2→3→4→5 |
| **각인** | rune | 칸에 붙는 확률적 규칙. **칸에 붙지 카드에 붙지 않는다**(§3.3 하단 근거) |
| **과열** | heat | 이번 사이클에 각인이 터진 횟수. 화력↑ 확률↓ RELOAD↑ |
| **일탈** | deviation | 각인 1회 발동. 과열 카운터를 올리는 사건 |
| **재진입** | re-entry | 이번 사이클에 이미 실행한 칸에 바늘이 다시 들어오는 것 |
| **결속** | link | 인접한 칸이 같은 태그를 공유해 형성되는 구간 |

### 3.2 바늘 실행 규칙 (정규 알고리즘)

한 스텝 = 한 칸의 카드를 끝까지 실행하고, 각인을 굴려 다음 위치를 정하는 것.

```text
# 상태: cursor(0..4), deviations(int, 무제한), executed[5](int, 각 칸 실행 횟수),
#       reload_debt(float), step_count(int)

STEP:
  1. slot = deck[cursor]
  2. reentry = executed[cursor]              # 0이면 첫 실행
     executed[cursor] += 1
     step_count += 1
  3. heat = min(deviations, HEAT_MAX)
     damage_mul = (1 + heat * HEAT_DAMAGE) * pow(REENTRY_FALLOFF, reentry)
  4. 카드 실행 (duration 만큼) — 기존 CycleSkillEffect 파이프 그대로
  5. reload_debt += card.reload
  6. --- 각인 판정 ---
     repeat = 0 ; delta = 0 ; reverse = false
     for rune in slot.runes:
         if not rune.condition_ok(): continue
         p = clamp(rune.p * pow(HEAT_DECAY, deviations), 0, P_CAP)
         if rng.randf() < p:
             deviations += 1
             apply(rune) -> repeat += / delta += / reverse = true
  7. --- 이동 결정 ---
     if repeat > 0:
         repeat = min(repeat, REPEAT_CAP)   # 같은 칸 연속 재실행 상한
         cursor 유지 (repeat 횟수만큼 STEP 반복 예약)
         goto STEP
     if reverse: direction *= -1
     next = cursor + direction * (1 + delta)
     if step_count >= STEP_CAP:  goto CYCLE_END(과부하)
     if next > 4 or next < 0 and direction < 0 and cursor == 0:
         goto CYCLE_END
     cursor = clamp(next, 0, 4)
     goto STEP

CYCLE_END:
  reload = min(reload_debt * (1 + heat * HEAT_RELOAD), RELOAD_CAP)
  RELOAD 대기
  deviations = 0 ; executed[] = 0 ; reload_debt = 0 ; step_count = 0
  cursor = 0 ; direction = +1
```

**경계 규칙 (엣지케이스 명시)**

| 상황 | 결과 | 근거 |
|---|---|---|
| 1칸에서 되감기 발동 | **1칸에 머문다(클램프)** — 5칸으로 감싸지 않는다 | 감싸면 꼬리에서 무한 순환 가능. 클램프는 "맨 앞으로 되감김"으로 직관적 |
| 5칸에서 도약 발동 | 사이클 **조기 완료** | 템포 빌드에게 실질 보상(마지막 칸의 RELOAD를 안 냄) |
| 되감기 2 + 도약 1 동시 발동 | delta = −2 +1 = **−1** (대수합) | 결정적이고 설명 가능. 각각 과열 +1씩 총 +2 |
| 재실행 + 되감기 동시 | **재실행 우선**, 되감기는 그 스텝의 delta로 이월 | 재실행은 "이동 없음"이라 먼저 소화해야 순서가 유일해짐 |
| 역행 중 1칸 도달 | 사이클 완료 | 역행이 무한 왕복이 되지 않게 하는 종결 조건 |
| STEP_CAP 도달 | 즉시 사이클 완료 + 화면 "과부하" 플래시 + RELOAD 상한 적용 | 하드 안전망(§3.9) |

### 3.3 각인 카탈로그 (24종 초안)

각 각인은 `{id, 계열, 기본확률 범위, 등급, 조건}` 을 가진다. **확률은 드래프트 시 범위 안에서 굴린다**
— 같은 각인이라도 "되감기 19%"와 "되감기 41%"는 다른 물건이다. 이게 "옵션이 랜덤하게 붙는" 감각의 핵심이다.

#### A. 흐름 (Flow) — 바늘을 움직인다

| id | 이름 | 효과 | 확률 범위 | 등급 |
|---|---|---|---|---|
| `rewind_1` | 되감기 | delta −1 | 18~42% | 일반 |
| `rewind_2` | 깊은 되감기 | delta −2 | 12~28% | 희귀 |
| `skip_1` | 도약 | delta +1 (그 칸 미실행) | 20~45% | 일반 |
| `repeat` | 앙코르 | 같은 칸 1회 더 | 15~35% | 일반 |
| `echo` | 메아리 | **이전 칸의 카드**를 여기서 위력 60%로 추가 발동 (이동 없음) | 20~40% | 희귀 |
| `reverse` | 역행 | 진행 방향 반전 (5→4→3…) | 10~22% | 영웅 |
| `bookmark` | 각인점 | 이 칸을 표식으로. 다른 칸에서 표식으로 점프 | 12~25% | 영웅 |
| `kill_repeat` | 도륙 | **이 칸으로 적을 처치하면** 앙코르 (확률 아님, 조건) | — | 희귀 |

#### B. 동시 (Parallel) — 칸을 결합한다

| id | 이름 | 효과 | 확률 범위 | 등급 |
|---|---|---|---|---|
| `link_next` | 연결 | 다음 칸을 **이 칸과 동시 실행**하고 바늘은 그 칸을 통과 | 18~38% | 희귀 |
| `chorus` | 합주 | 양옆 칸의 피해 스킬이 위력 30%로 동반 발동 | 25~50% | 일반 |
| `overlap` | 겹침 | 이 칸의 duration 동안 **이전 칸 효과가 잔류** | 확정 | 일반 |

> **Note**: 이 세 각인이 v1의 "분열(3레인)"을 대체한다. 같은 판타지(동시 발동)를 UI 밀도 증가 없이 얻는다.

#### C. 조건 (Conditional) — 5칸이 서로를 본다

| id | 이름 | 효과 |
|---|---|---|
| `tag_chain` | 연쇄 | 직전에 실행한 칸이 같은 태그면 피해 +25~55% |
| `heat_gate` | 열기 | 과열 ≥3일 때만 발동, 발동 시 피해 ×1.8 |
| `first_strike` | 선봉 | 이번 사이클 **첫 실행**이면 피해 +40~80% |
| `last_call` | 마감 | 이번 사이클 **재진입**이면 RELOAD −0.15초 |
| `odd_even` | 홀짝 | 홀수 번째 실행이면 피해 +, 짝수면 범위 + |

#### D. 템포 (Tempo) — 시간을 만진다

| id | 이름 | 효과 |
|---|---|---|
| `haste` | 단축 | 이 칸 duration −12~25% |
| `refund` | 상환 | 이 칸 실행 시 누적 RELOAD 빚 −0.2~0.5초 |
| `toll` | 통행세 | 이 칸을 **도약으로 건너뛸 때마다** 빚 −0.4초 |
| `free_reload` | 무상 | 확률적으로 이 칸의 reload를 0으로 (25~50%) |
| `afterburn` | 잔열 | RELOAD 후 과열을 `floor(H/2)`만큼 유지 |

#### E. 전투 (Combat) — 기존 아이템 효과 어휘 재사용

`damage +x%` / `range +x%` / `hits +1` / `pierce +n` / `crit +x%` / `lifesteal +x%` / `knockback` / `shield +1`
— **`item_library.gd`의 `effects` 키를 그대로 쓴다.** 신규 어휘를 만들지 않는다.

#### 설계 결정: 각인은 **칸**에 붙는다 (카드가 아니라)

사용자 원문은 "각 스킬을 강화하면"이지만, 구현·플레이 양쪽에서 **칸 부착**이 우월하다.

- **근거 1 (의미론)**: 흐름 각인의 의미가 위치적이다. "이 칸에서 2칸 뒤로"는 칸의 성질이지 카드의 성질이 아니다.
- **근거 2 (플레이)**: 카드를 자유롭게 재배치하며 흐름을 재조립할 수 있다 → "조립하는 것 자체가 게임"이라는 요구에 직결.
- **근거 3 (구현)**: 보관함에 있는 카드가 각인을 들고 다니는 상태를 관리하지 않아도 된다. 저장 스키마가 단순해진다.
- **UI 보정**: 드래프트 화면은 "**강화할 칸을 고르세요**"라고 묻고 그 칸에 현재 놓인 카드를 크게 보여준다.
  플레이어 체감은 "이 스킬을 강화한다"에 가깝게 유지된다.
- **연결 복원**: `tag_chain`·`heat_gate` 같은 조건 각인이 카드의 태그를 읽으므로, 카드↔각인 궁합은 살아 있다.

> **반대 의견 기록**: 카드 부착이면 "이 스킬 내가 키웠다"는 RPG적 애착이 강해진다.
> 만약 플레이테스트에서 "칸을 키우는 게 밋밋하다"는 피드백이 나오면, 각인 중 **E계열(전투)만 카드 부착**으로
> 옮기는 하이브리드가 최소 변경 대안이다.

### 3.4 확률·중첩·우선순위 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| **중첩** | 같은 칸에 같은 id 각인 2개 → `p = 1 − (1−p₁)(1−p₂)` (여집합 곱) | 선형 합산은 100%에 도달해 잠금 루프를 만든다 |
| **상한** | 최종 확률 `P_CAP = 0.75` | 확정 발동이 없어야 "룰렛" 감각과 종료성이 동시에 유지된다 |
| **과열 감쇠** | `p_eff = p × HEAT_DECAY^deviations` (deviations는 **캡 없는** 실제 발동 횟수) | 감쇠의 근거를 캡에 두면 캡 도달 후 감쇠가 멈춰 종료성이 깨진다 |
| **독립 굴림** | 한 칸의 각인들은 서로 독립적으로 굴린다 | 설명 가능성. "3개 중 몇 개가 터질지"가 그날의 운 |
| **비용** | 발동한 각인마다 `deviations += 1` (효과 크기와 무관) | 단순·예측 가능. 강한 각인은 확률이 낮게 저작됨 |
| **순서** | `repeat` → `delta 합` → `reverse` | §3.2 표 참조 |
| **조건 각인** | 조건 불충족이면 굴리지도 않는다(과열 소모 없음) | 조건부가 확률 예산을 먹지 않게 |

### 3.5 과열(Heat) — 루프 방지 장치를 게임의 도파민으로

**핵심 아이디어**: 루프를 막는 감쇠와 루프를 보상하는 화력을 **같은 카운터**에 묶는다.

```text
deviations : 이번 사이클 각인 발동 총 횟수 (감쇠용, 상한 없음)
heat       : min(deviations, HEAT_MAX)     (표시·보상용)

발동 확률   ×= HEAT_DECAY ^ deviations      # 0.62^n
피해 배율   ×= 1 + heat × HEAT_DAMAGE       # +12%/스택, 최대 +96%
RELOAD     ×= 1 + heat × HEAT_RELOAD        # +18%/스택, 최대 +144%
```

플레이 체감:
- 평범한 사이클: 각인 2~3회 발동 → 과열 3 → 화력 +36%, RELOAD +54%. 무난하다.
- **대박 사이클**: 초반에 연달아 5~6회 터짐 → 화력 +72% 상태로 5칸을 두 바퀴 → 화면이 지워진다.
  그리고 곧바로 3초짜리 RELOAD가 와서 벌거벗은 채 도망쳐야 한다.
- 이 "폭발 → 무방비" 리듬이 v2의 전투 문법이다. 대시(기존 10초 쿨)가 여기서 진짜 의미를 갖는다.

**시각화**: HUD 우측 온도계 + 레일 전체가 과열 단계마다 색온도 상승(청→금→적).
RELOAD 중에는 레일이 식으면서 기존 **되감기 릴 연출**(`CYCLE_REWIND_*`)을 그대로 재사용한다.

### 3.6 재진입 감쇠 — 넓은 루프를 좋게, 좁은 루프를 나쁘게

```
damage_mul ×= REENTRY_FALLOFF ^ (이번 사이클에 이 칸을 이미 실행한 횟수)   # 0.82^n
```

이 한 줄이 축퇴 빌드를 구조적으로 막는다.

| 빌드 | 계산 | 결과 |
|---|---|---|
| 2칸 핑퐁 (A↔B 반복) | 과열 +12%/스텝 × 재진입 0.82/스텝 ≈ **0.918^n** | 감소 → 비최적 |
| 3칸 순환 (A→B→C→A…) | 각 칸 재진입 1~2회, 과열은 6스택 | 강한 순증 → **최적** |
| 5칸 두 바퀴 | 재진입 1회씩, 과열 5~7 | 최강. 하지만 확률이 이미 다 식음 |

→ **"넓게 돌려라"** 가 자연스럽게 지배 전략이 되고, 그건 5칸을 전부 쓰라는 뜻이다. 정확히 의도한 바다.

### 3.7 RELOAD 재정의

v1: 한 바퀴 후 "실행된 모든 카드의 reload 합계"를 대기.
v2: **빚(debt) 누적 모델**로 바꾼다.

```
카드를 실행할 때마다 reload_debt += card.reload
사이클 종료 시 RELOAD = min(reload_debt × (1 + heat × HEAT_RELOAD), RELOAD_CAP)
```

- 되감아 카드를 다시 실행하면 그 reload를 **또** 낸다 → 루프의 진짜 비용이 여기 있다.
- 도약으로 건너뛴 칸은 reload를 내지 않는다 → 도약 빌드의 정체성.
- HUD에 **누적 빚이 실시간으로 차오른다.** "화력 게이지"와 "빚 게이지"가 나란히 오르는 그림이
  이 게임의 시그니처 화면이 된다.
- `RELOAD_CAP = 6.0초`. 넘어가면 게임이 멈춘 것처럼 느껴진다.

### 3.8 5칸 상호작용 — 태그·공명·반응

각 스킬 카드는 **원소 태그 1개 + 형태 태그 1개**를 갖는다.

- 원소(6): `화(炎)` `빙(氷)` `뇌(雷)` `광(光)` `혈(血)` `철(鐵)`
- 형태(5): `참격` `관통` `파동` `설치` `수호`

| 규칙 | 내용 | 구현 비용 |
|---|---|---|
| **인접 공명** | 이웃한 두 칸이 **같은 원소**면 두 칸 모두 피해 +15% | 순수 숫자 판정. 무료 |
| **결속 구간** | 같은 원소가 3칸 이상 연속 → 그 구간 안에서 발동하는 각인은 **과열을 올리지 않는다** | 흐름 엔진에 조건 1줄. 매우 강력한 빌드 축 |
| **삼각 배열** | 1·3·5칸이 같은 형태 태그 → 전체 RELOAD −12% | 무료 |
| **원소 반응** | 3종만: 빙→뇌 = 감전(광역 추가), 화→빙 = 증기(범위 +50%), 화→뇌 = 과충전(과열 +1 무상) | VFX 3개 필요 → **선택 웨이브** |

> **결속 구간이 이 시스템의 최고 설계 지점이다.** "같은 원소를 몰아 놓으면 그 안에서는 공짜로 루프할 수 있다"는 규칙은
> ①태그 정렬이라는 퍼즐 ②흐름 각인의 배치 ③과열 관리를 하나로 묶는다.
> 대신 원소를 섞으면 태그 시너지는 없지만 반응(콤보)을 얻는다. **두 개의 상반된 빌드 철학**이 자연 발생한다.

### 3.9 무한 루프 불가능성 — 4중 안전망

| 층 | 장치 | 보장 |
|---|---|---|
| 1 | `P_CAP = 0.75` | 어떤 각인도 확정 발동이 아니다 |
| 2 | `HEAT_DECAY^deviations` | 발동 확률이 기하급수적으로 0에 수렴 → 스텝 수 기댓값 유한 |
| 3 | `STEP_CAP = 14` | 확률이 아무리 나빠도 14스텝이면 강제 종료(과부하) |
| 4 | `RELOAD_CAP = 6.0s`, `REPEAT_CAP = 2` | 종료 후 대기가 무한히 길어지지 않음 |

**기댓값 추정** (최악 빌드: 5칸 × 각인 3개 × 확률 0.75, 모두 흐름 각인):
스텝당 기대 발동 = 2.25 → 과열이 즉시 오르며 `2.25 × 0.62^n` 으로 감쇠.
누적 기대 발동 ≈ 2.25 + 1.40 + 0.86 + 0.54 + 0.33 + … ≈ **5.9회** → 총 스텝 ≈ **10.9**.
STEP_CAP 14 도달 확률은 낮고, 도달해도 과부하 처리로 정상 종료한다.

> **검증 필수**: 이 추정은 해석적 근사다. W1에서 **10,000 사이클 몬테카를로**로
> `평균 스텝 < 11`, `STEP_CAP 도달률 < 3%`, `무한 루프 0회`를 실측한다. 실측이 다르면 상수를 조정한다.

### 3.10 빌드 다양성 검증 — 아키타입 5종

| 아키타입 | 축 | 코어 각인 | 태그 전략 | 느낌 |
|---|---|---|---|---|
| **되감기 엔진** | 과열 극대화 | `rewind_1`×2, `afterburn`, `heat_gate` | 3칸 결속(무상 루프) | 사이클마다 폭발과 침묵의 진폭이 극단적 |
| **도약 템포** | 빚 최소화 | `skip_1`, `toll`, `haste`, `free_reload` | 삼각 배열 | 5칸을 2.8초에 도는 초고속 회전 |
| **메아리 중첩** | 단일 칸 화력 | `echo`, `link_next`, `chorus` | 원소 반응 | 한 칸에서 3개가 동시에 터짐 |
| **역행 진자** | 순서 이중 설계 | `reverse`×2, `odd_even`, `bookmark` | 대칭 배치 | 레일을 양방향으로 읽히게 짜는 퍼즐 |
| **도륙 연쇄** | 처치 기반 | `kill_repeat`, `first_strike`, 광역 카드 | 화·뇌 | 잡몹 무리에서만 미친 듯이 굴러감 (밤 특화) |

5개 모두 **같은 5칸**에서 서로 다른 답을 요구한다. 다양성 요건 충족.

## 5. 성장과 드래프트

### 5.1 두 화폐: 카드와 각인

| 화폐 | 무엇 | 어디서 | 미선택 시 |
|---|---|---|---|
| **카드(스킬)** | 5칸에 놓을 행동 | 홀수 레벨업 2택1, 성 상점, 전조 회수 | 마왕의 칸으로 |
| **각인** | 칸에 붙는 규칙 | 짝수 레벨업 3택1, 균열 보상, 성 각인상점, 계약 | 마왕의 각인 재료로(2개당 1) |

**런당 총량 추정 (7일, 레벨 15 기준)**

```
레벨업 15회 → 스킬 8장 접촉 / 각인 7개
균열 3회        → 각인 3
성 각인상점     → 각인 2~3 (골드)
각성 2회        → 특별 카드 2
─────────────────────────────
보유 각인 ≈ 12~13   vs   각인 슬롯 15 (5칸 × 3)
```

**슬롯이 항상 모자란다.** 이게 중요하다 — 끝까지 "어디에 넣지"라는 결정이 남는다.

### 5.2 랭크(수치) vs 각인(행동)

두 성장 축의 역할을 완전히 분리한다.

- **랭크**: 카드에 붙는다. 같은 id 2장 → 랭크+1. **상한 R3** (v1의 R5는 7일 런에서 도달 불가 — 16장 필요).
  - `DealCardLibrary.ranked()` 계수 재조정: 피해 `×(1 + (r−1)×0.55)`, duration `×0.94^(r−1)`, reload `×0.95^(r−1)`
  - R3 = 피해 ×2.1. v1의 R5(×2.36)와 비슷한 상한을 4장으로 도달.
- **각인**: 칸에 붙는다. **행동만** 바꾼다.

한 문장으로: **랭크는 숫자를 키우고, 각인은 규칙을 바꾼다.**

### 5.3 각성(Awakening) — 전직 시스템 대체

v1의 전직 조건(R5 카드 2종 + 무기 / 동서남북 시련 4곳 순회)은 **7일 런에서 물리적으로 도달 불가**다.

**대체안**: 시간 이정표 + 가벼운 조건.

| 시점 | 이름 | 조건 | 보상 |

| 6일차 새벽 | **2차 각성** | 해당 계보 태그 각인 3개 이상 보유 | 2차 특별 카드 2택1 + 스탯 |

- 기존 `evolution` / `advancement_choice` 상태와 UI도 그대로 재사용.

### 5.4 아이템 → 장비 전환 (57종 전량 유지)

**문제**: 5칸에서 아이템에 한 칸을 주면 전력의 20%를 포기하는 것이다. 그리고 아이템의 효과 어휘
(`damage_next`, `duration_adjacent`, …)는 각인 E계열과 **같은 설계 공간**이다. 두 시스템이 같은 일을 한다.

**해법**: 아이템을 **레일 밖 장비 4칸**(무기/목걸이/반지/팔찌)으로 옮긴다.

| 스코프 키 | v1 의미 | v2 의미 | 코드 변경 |
|---|---|---|---|
| `*_all` | 전체 레일 | 전체 레일 (불변) | 없음 |
| `*_next` | 아이템 칸의 다음 칸 | **바늘이 다음에 실행할 칸** | `_apply_item_modifiers`에 `playhead_index` 인자 추가 |
| `*_previous` | 아이템 칸의 이전 칸 | **직전에 실행한 칸** | 동상 |
| `*_adjacent` | 앞뒤 | 직전 + 다음 | 동상 |
| `*_paired` | 같은 칸 다른 레인 | (레인 폐지) → **현재 실행 중인 칸 자신** | 동상 |

> **이게 오히려 더 좋다**: 되감기가 발동하면 "다음 칸"의 정체가 바뀐다.
> 장비 효과가 **흐름을 인식하게** 되어, 장비와 각인이 서로를 참조한다.

**결과: `item_library.gd` 데이터 57종을 한 줄도 고치지 않는다.** 위치와 해석만 바뀐다.
상점·보물상자 2택1·미선택→마왕 규칙도 전부 유지.

### 5.5 균열(Rift) — 시련 캠프 대체

- 2·4·6일차 낮 시작 시, **플레이어 기준 900~1,400px** 지점에 균열 1개 생성(월드에 아이콘 표시 + 나침반).
- 진입하면 원형 아레나 + 정예 3~5기(기존 `is_camp_elite` 로직 재사용, 배율은 ×5 → **×3**으로 하향).
- 클리어 보상: **각인 상자**(3택1) + 골드 + 체력 전회복.
- **동서남북 고정 4캠프는 폐기.** `world_grid.gd::TRIAL_CAMPS` 상수 제거, 동적 배치로 교체.
- `_draw_trial_camp()` 렌더러와 `_activate_trial_camp` / `_trial_enemy_defeated` 로직은 재사용.

## 6. 마왕

### 6.1 버린 카드 → 마왕의 5칸 — **유지 확정**

> **판단: 유지하고 오히려 강화한다.** 설계상 충돌이 없을 뿐 아니라, 5칸 리부트가 이 메커니즘을
> **처음으로 읽히게** 만든다. v1은 10칸×2레인=20칸이라 플레이어가 마왕의 빌드를 이해할 수 없었다.
> 5칸이면 "내가 3레벨에 버린 벼락 심판이 저기 있다"가 한눈에 보인다.

배치 규칙:
1. 받은 카드 중 같은 id를 자동 합성(랭크 상승) — **`_boss_auto_fused_cards()` 그대로 재사용**
2. `DealCardLibrary.expected_power()` 상위 **5장**을 1~5칸에 배치 — **함수 그대로 재사용**
3. 남은 카드는 **잔재**가 되어 밤 필드 몹에게 모듈로 뿌려진다(§6.4)
4. 버린 아이템은 `boss_items`로 마왕 스탯에 — **`_apply_boss_items()` 그대로 재사용**

### 6.2 마왕도 각인으로 자란다 (H1의 핵심)

- **각인 수** = `min(floor(받은 카드 수 / 2), 12)`. 짝수 레벨업의 미선택 각인 2장도 여기에 기여.
- 마왕의 각인은 **무작위 배치**되고, **프리뷰에서 전부 공개**된다.
- **마왕에게도 과열·재진입 감쇠·RELOAD가 똑같이 적용된다.** (v1은 RELOAD 없음 = 무한 압박이었다)
  - 마왕 RELOAD 배율 `×0.6` — 플레이어보다 빠르지만 **반격 창은 존재**한다.
  - 마왕의 과열 게이지가 화면에 보인다 → "지금 과열 6, 피하고 버텨라 → RELOAD 왔다, 지금 때려라"
  - **이것이 v2 보스전의 문법이다.** 대칭 규칙 + 읽히는 텔레그래프 + 명확한 반격 창.

### 6.3 마왕 HUD 고스트 레일 (상시 압박)

필드 HUD 우상단에 **마왕의 5칸 미니 레일**(칸당 44×32)을 상시 표시.
- 실루엣 아이콘 + 각인 개수 배지만. 상세는 `Tab`으로 확대.
- 카드를 버릴 때마다 해당 칸이 번쩍이고 기존 **마왕 토스트**(3초, 큐 최대 3)가 뜬다 — 그대로 유지.

### 6.4 잔재 → 필드 몹

상위 5장에 들지 못한 버린 카드는 사라지지 않는다.
`DealCardLibrary.debt_module()`(이미 존재)이 카드를 모듈로 환산해 밤 몹에게 랜덤 부여한다 — **v1 코드 그대로.**
5일차 **월식** 때는 이 부여율이 100%가 된다.

→ 버린 카드가 **하나도 낭비되지 않는다.** 상위 5장은 마왕의 칸으로, 나머지는 밤의 마물로.

### 8.2 편집 화면(ESC) — 레일 + 흐름 아크

**스크롤 없음이 구조적으로 보장된다**: 카드 196 × 5 + 커넥터 44 × 4 = **1,156px** (좌우 여백 62px).
(현재 `FACTORY_RAIL_CARD_W=200`, `BRIDGE_W=70` → 5칸이면 1,280px 정확히 = 여백 0. 반드시 축소해야 한다.)

```text

  ▼                                     ▼
┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐

│ 벼락 │  │ 화염 │  │ 회전 │  │ 미개방│  │ 미개방│
│ R2 雷│  │ R1 火│  │ R3 火│  │      │  │      │

```

- **흐름 아크**: 각인의 이동을 카드 위쪽 반원 호로 그린다. 확률 라벨 포함. `draw_arc`만으로 구현.
  → 플레이어가 "내 회로가 어떻게 흐르는가"를 **한 화면에서** 이해하는 유일한 장치.
- **예상 지표**: 편집 중 실시간 몬테카를로 200회(1프레임 내 계산 가능)로 평균 스텝/화력/사이클 시간 표시.
  이게 있어야 각인 배치가 도박이 아니라 **설계**가 된다.
- 결속 구간은 카드 하단에 연속 밴드로 표시.

> **검토 후 기각한 대안 — 원형(시계) 레이아웃**: 되감기가 반시계 회전으로 읽히는 건 매력적이지만,
> 1280×720에서 5장의 카드에 이름·랭크·각인 3개를 담으려면 링이 화면 중앙을 다 먹는다.
> 필드 HUD로는 불가. **레일 + 흐름 아크가 같은 정보를 더 싸게 준다.**

### 9.5 화력 곡선 대조 (7일차 기준, 추정)

```
플레이어 피해 배율 ≈ 랭크(×1.8) × 각인 E계열(×1.4) × 장비(×1.5) × 과열 평균(×1.35) ≈ ×5.1
사이클 효율 ≈ 5칸 → 평균 8.3스텝 (각인 일탈 3.3회분 추가 타격)
몬스터 체력 배율 ≈ ×2.68 (일수) × 상위종 slash_hits 3→12 (×4) ≈ ×10.7
```
→ 플레이어가 뒤처진다. **의도적이다**: 7일차는 위험해야 한다. 다만 ×10.7은 과할 수 있으므로
`CYCLE_HEALTH_GAIN`을 0.28→0.24, 최상위 몹 `slash_hits`를 12→10으로 낮추는 것을 1차 조정안으로 둔다.

### 명시적으로 답하지 못한 것 (추측 구간)

- Godot 4.7 **GL Compatibility 렌더러에서 WorldEnvironment 글로우가 동작하는지** 확인하지 않았다.
  안 되면 가산 합성 스프라이트 헤일로로 대체(현 VFX가 이미 유사 방식이라 위험 낮음).

## 부록 C. 확정된 결정 (2026-08-07, 이 섹션이 본문과 충돌하면 이 섹션이 우선)

구현 웨이브 에이전트는 반드시 이 섹션을 본문보다 우선 적용한다.

1. **각인 = 칸 부착 확정** (사용자 승인). 추가 요구 2건:
   - **한 칸에 각인 중복 강화 가능** — 같은 칸을 여러 번 강화해 각인을 누적할 수 있다. 스택 상한·중복 조합 규칙은 §3.3의 확률 상한(P_CAP)·과열 감쇠 안에서 W1이 정의하되, "한 칸 몰빵"이 유일 정답이 되지 않게 감쇠를 설계할 것.
   - **칸 자체의 위치 이동 가능** — 카드만 칸 사이를 옮기는 게 아니라, 칸(각인 포함)을 통째로 다른 위치와 교환할 수 있다. 즉 편집 화면에서 [카드 이동]과 [칸 순서 교환] 두 조작이 공존하며, 칸을 옮기면 붙어 있던 각인이 함께 이동한다.
2. **v1 git 스냅샷 없음** (사용자 결정). 어떤 웨이브도 git commit을 하지 않는다. W0의 "Git 최초 커밋" 항목은 폐기. 대신 파괴적 삭제 전 해당 파일의 원본을 `docs/v1-archive/`에 복사해 두는 것으로 대체한다(코드 복구용, preload 대상 아님).
3. **아이템 레일 이탈**(§5.4), **시련 캠프 폐기→동적 균열**(§5.5), **버린 카드→마왕 유지+강화**(§6) — 오케스트레이터 승인으로 확정.
4. **아트 톤**: 에셋 수급 에이전트의 조사 결과가 확정한다(§8.5의 픽셀 유지 가정은 잠정). `godot-game/art/external/LICENSES.md`·`INVENTORY.md`가 W11의 착수 게이트.
